БЕЗОПАСНОСТЬ В ЭТОМ ОБНОВЛЕНИИ (9 октября 2026)

LocalLS теперь умеет входить по приватному SSH-ключу. Ключ пользователя
и SSH host key сервера — разные вещи: первый разрешает вход, второй помогает
проверить, что вы подключаетесь к известному серверу.

ПЕРЕХОД С ПАРОЛЯ БЕЗ ПОТЕРИ ДОСТУПА
1. Обновите приложение поверх прежней версии. Не удаляйте данные приложения.
2. Подключитесь прежним способом и сверьте SSH fingerprint с сервером.
3. Откройте Настройки → Безопасность / SSH-ключ. На Android пункт находится
   внутри настроек приложения. Создайте RSA 3072 или импортируйте свой ключ.
4. Для Windows/Fedora сначала включите «Сохранить секреты» в «Подключение»
   и сохраните настройки. Это доступно только при работающем системном
   шифровании. Без этой опции созданный ключ живёт только до полного выхода.
   При недоступной связке ключей используйте импорт имеющегося ключа,
   исходный файл храните отдельно, защищайте парольной фразой и правами доступа.
   Android сохраняет ключ зашифрованным средствами Android Keystore.
5. В разделе безопасности введите действующий пароль в поле установки ключа.
   Нажмите «Установить ключ и проверить вход» и подтвердите адрес/пользователя.
6. Приложение добавит только публичную часть в ~/.ssh/authorized_keys,
   сохранит существующие строки, выставит .ssh 700 и authorized_keys 600.
   Оно выполнит новое соединение только по ключу. Лишь после успеха клиент
   переключается на ключ и удаляет сохранённый пароль текущего профиля.
7. Подключитесь заново, откройте SFTP и проверьте передачу файла.
8. Повторите на каждом устройстве. Лучше иметь отдельный ключ для каждого
   устройства: потерянный ключ можно отозвать отдельно на сервере.
9. Проверьте вход после полного выхода/повторного запуска приложения.
   Парольный режим сервера не отключайте до этой проверки и подготовки
   резервного доступа на самом серверном устройстве.

В режиме ключа неверный/потерянный ключ вызывает ошибку. Приложение
не пытается незаметно использовать пароль. Режим пароля можно выбрать
вручную для миграции, если сервер ещё разрешает такой вход.
Экспорт .pub содержит только публичный ключ. Экспорт профиля не переносит
приватный ключ, парольную фразу, пароль или токен. На другом устройстве
нужно создать/импортировать свой ключ и разрешить его на сервере.
Удаление локального ключа не отзывает ключ на сервере: для отзыва удалите
соответствующую строку authorized_keys, сохранив остальные ключи.
Удаление приложения/сброс данных Android может уничтожить ключ Keystore;
перед этим обеспечьте другой проверенный способ доступа. Экспорт приватного
ключа из приложения в этой версии не реализован.

УПРАВЛЯЮЩИЙ АГЕНТ: HTTPS
Обычный SSH/SFTP не требует агента. Агент нужен для Start/Stop/Restart SSH,
в том числе когда SSH уже остановлен. Это независимый канал управления.
Новая версия агента 0.3 использует TLS 1.2+ и случайный Bearer-токен.
Скачайте отдельно LocalLS-Agent-0.3.zip из нового релиза; распакуйте на
серверном устройстве. Сохраните резервную копию прежней конфигурации.
На сервере в Termux выполните ./install.sh из этой папки. Установщик
сохраняет существующие токен, адрес, порт и схему автозапуска, создаёт
сертификат RSA 3072 и выводит его SHA-256. Токен показан только владельцу;
не отправляйте этот вывод в публичные логи/issue/чат.
Работающий старый процесс не перезапускается установщиком: завершите именно
этот процесс агента прежним способом и запустите обновлённый вручную.
Не запускайте второй агент поверх занятого порта и не трогайте работающий sshd.
В LocalLS укажите прежний порт и токен. В «Безопасность» нажмите проверку
HTTPS-сертификата агента, сравните SHA-256 с сервером и подтвердите.
Во время получения сертификата токен не отправляется. До доверия запросы
заблокированы; при смене сертификата они также блокируются. Подтверждайте
новый отпечаток только после независимой проверки на сервере.
Сертификат действует 365 дней; обновляйте его заранее и проверяйте новый pin.
Самоподписанный сертификат здесь доверяется по точному отпечатку, а не
просто потому, что сеть названа домашней. Первое подтверждение — ваша проверка.
Старый HTTP-агент работает только при явном включении временной совместимости.
Тогда токен передаётся без TLS, и приложение требует подтверждение действий.
По умолчанию этот режим выключен. Для нового агента оставьте его выключенным.

ПАРОЛЬНЫЙ ВХОД НА СЕРВЕРЕ
Это обновление НЕ отключает его автоматически и не меняет sshd_config,
порт SSH или механизмы запуска sshd. Клиентский вход только по ключу
не означает, что другой клиент больше не может войти на сервер по паролю.
После проверки всех ключей администратор может отдельно запретить пароль:
  PubkeyAuthentication yes
  PasswordAuthentication no
  KbdInteractiveAuthentication no
  AuthenticationMethods publickey
На Termux конфигурация обычно $PREFIX/etc/ssh/sshd_config; на Fedora —
/etc/ssh/sshd_config и включаемые файлы. Нужна проверка Include/Match,
резервная копия и проверка синтаксиса sshd -t перед применением.
Проверьте эффективные параметры sshd -T для нужного пользователя/адреса;
перезапустите службу штатным существующим способом при доступном резервном
сеансе и проверьте новое независимое подключение. Root/админ-права нужны
только там, где этого требует серверная ОС. Не копируйте настройки вслепую.

СЕТЬ И ИНТЕРНЕТ
Интернет на сервере для обновлений не означает доступ к нему из интернета.
Порт 8022 вместо 22 уменьшает часть шума, но не заменяет ключи и firewall.
Не делайте проброс SSH/агента на роутере, проверьте UPnP и правила IPv6:
IPv6 не обязательно защищён NAT. Для удалённого доступа используйте Tailscale
с ограниченными grants/ACL, проверенными устройствами и защищённым аккаунтом.
Открытие SSH через мастер Fedora разрешает сервис в текущей firewall-зоне;
это не автоматически ограничивает доступ только вашей домашней подсетью.
Проверьте зону/интерфейс/разрешённые источники средствами Fedora.
Отсутствие публичной доступности вашего сервера не проверено из этой среды.
Не публикуйте приватные ключи, токены, личные профили или конфигурацию агента.

LOCALLS ДЛЯ ANDROID — ПОДРОБНАЯ ИНСТРУКЦИЯ
Версия приложения: 0.9.4. Документ: 9 октября 2026.

ДОБРО ПОЖАЛОВАТЬ В LOCALLS!

Ваши файлы — рядом, даже когда сервер находится на другом устройстве.
LocalLS помогает пользоваться личным сервером с телефона: открывать папки,
отправлять фотографии и документы, скачивать нужные файлы и видеть ход передач.
Дома подключайтесь по Wi-Fi, а вне дома — через настроенный Tailscale.
Если вы только создаёте сервер на Android, встроенный мастер поможет подготовить
Termux/OpenSSH через понятные шаги и системные подтверждения.
Для начала подключитесь к работающему серверу или откройте мастер на том телефоне,
который будет сервером. Ваши файлы передаются между вашими устройствами;
LocalLS не предоставляет собственное облачное хранилище.

1. ЧТО НАХОДИТСЯ В ЭТОЙ ПАПКЕ

В архиве LocalLS-Android-0.9.4-with-guides.zip находится папка Android:
  LocalLS-v0.9.4-debug.apk — приложение для установки;
  INSTRUCTIONS_RU.txt — эта инструкция;
  INSTRUCTIONS_EN.txt — инструкция на английском;
  BUILD_REPORT.md — результаты сборки и выполненных проверок;
  SHA256SUMS.txt — контрольные суммы файлов.
Оба TXT-документа открываются обычным текстовым редактором или Блокнотом.
На GitHub в distributions/Android размещены документы и ссылки на установщик.
Готовый архив и APK скачиваются из Assets релиза android-v0.9.4.

2. ДЛЯ ЧЕГО НУЖНА ПРОГРАММА

LocalLS подключается к вашему SSH/SFTP-серверу: показывает файлы, отправляет
и скачивает их, отображает скорость, очередь и историю. Отдельные меню
содержат подключение, оформление, Wi-Fi, VPN/Tailscale и инструменты сервера.
Приложение может работать клиентом на одном телефоне и помогать подготовить
Termux/OpenSSH на другом телефоне, если LocalLS установлен и на сервере.
Мастер дополняет обычную настройку Termux. Уже работающий сервер можно
продолжать использовать без повторной подготовки.

3. СИСТЕМНЫЕ ТРЕБОВАНИЯ И УСТАНОВКА

Нужен Android 7.0 или новее. Для подключения нужен доступ к серверу по сети.
1) Скачайте APK либо ZIP и распакуйте папку Android.
2) Откройте LocalLS-v0.9.4-debug.apk на телефоне.
3) Если Android запросит разрешение устанавливать из этого источника,
   разрешите его вашему браузеру или файловому менеджеру и повторите установку.
4) Откройте LocalLS. На Android 13+ разрешите уведомления для передач в фоне.
5) Если программа уже установлена, обновляйте поверх неё. Не удаляйте её
   заранее, если хотите сохранить настройки, историю и доверенные ключи.
APK подписан debug-сертификатом. Ошибка несовместимой подписи означает,
что установленная копия подписана другим ключом. Сначала сохраните параметры
и публичный профиль; удаление приложения удаляет его локальные данные.
Не требуется устанавливать Android SDK, Java или средства разработки.

4. ПОДКЛЮЧЕНИЕ К УЖЕ РАБОТАЮЩЕМУ СЕРВЕРУ

Сначала подключите телефон и сервер к одной доступной локальной сети.
В правой боковой шторке раскройте «Подключение» и укажите:
  IP/имя сервера — например, 192.168.1.82;
  SSH-порт — например, 8022;
  Пользователь Termux — например, u0_a606.
Эти значения приведены как пример. На другом сервере адрес и пользователь
могут отличаться. Не добавляйте http://, https:// или :порт к полю IP.
Введите действующий SSH-пароль в поле пароля на основном экране.
При желании включите «Сохранить пароль в Android Keystore» и сохраните
настройки. Без сохранения после нового запуска может потребоваться пароль.
Нажмите «Проверить SSH»/«Проверить сервер», затем откройте «Файлы».
Сервер должен уже иметь запущенный OpenSSH и поддержку SFTP.

5. ПЕРВЫЙ ВХОД И ОТПЕЧАТОК SSH-КЛЮЧА

При первом подключении LocalLS показывает fingerprint — отпечаток ключа.
Сверьте его с данными сервера или с проверенным профилем от его владельца.
Только после сверки нажимайте «Доверять этому fingerprint».
Изменение уже сохранённого ключа блокирует подключение до отправки пароля.
Проверьте, не изменился ли IP и не оказался ли по этому адресу другой сервер.
Если вы сами переустановили сервер и подтвердили новый ключ, используйте
«Забыть сохранённый fingerprint», затем повторно сверьте и подтвердите ключ.

6. КАК ОТКРЫВАТЬ ПАПКИ И СКАЧИВАТЬ ФАЙЛЫ

1) Откройте «Файлы». Обычное нажатие на папку открывает её.
2) «Открыть папку» или нажатие на строку пути позволяет указать полный путь
   на сервере. Используйте путь, доступный пользователю SSH.
3) Нажмите «Выделить» или долго нажмите на файл и отметьте нужные файлы.
4) Можно переходить в другие серверные папки: выделение файлов сохраняется.
5) Нажмите «Скачать выбранное». В системном окне Android выберите папку
   телефона и подтвердите использование этой папки.
6) Следите за очередью, прогрессом, скоростью и результатом передачи.
Поддерживается выбор до 256 файлов. Если имя на телефоне уже занято,
новый файл получает свободное имя с номером; старый файл сохраняется.
Для одного файла также доступно скачивание через системный выбор документа.
Целые папки рекурсивно не скачиваются: откройте папку и выделите файлы внутри.
Некоторые корневые и системные папки Android недоступны в системном выборе.
Выберите разрешённую пользовательскую папку, например подпапку Downloads.

7. КАК ПРИКРЕПЛЯТЬ И ОТПРАВЛЯТЬ ФАЙЛЫ

1) Подключитесь к серверу и откройте папку назначения в проводнике.
2) Нажмите «Прикрепить» и выберите один или несколько документов телефона.
3) Проверьте вложения: ненужные можно убрать. Доступно до 64 вложений.
4) Проверьте серверный путь и нажмите «Отправить».
5) Подтвердите список файлов и папку назначения.
Выбор вложения сам по себе не запускает отправку. Также можно открыть файл
в другом приложении, нажать Android «Поделиться» и выбрать LocalLS.
После этого перейдите к вложениям в LocalLS и подтвердите отправку.
Одноимённый файл на сервере при отправке может быть заменён: проверьте путь
и список перед подтверждением. В 0.9.4 при обрыве такой отправки на сервере
может остаться частичный файл; повторите передачу и проверьте результат.

8. ОЧЕРЕДЬ, ГРАФИК, ИСТОРИЯ И РАБОТА В ФОНЕ

График SFTP показывает измеренную скорость текущих передач. Если передачи
не идут, отсутствие скорости нормально: это не измерение тарифа интернета.
История показывает выполненные, неуспешные и отменённые передачи.
Отменяйте нужную задачу кнопкой отмены очереди. При кратком обрыве сети
предусмотрена не более чем одна автоматическая повторная попытка.
Для продолжения передачи используйте кнопку Home или «Свернуть» в проводнике.
Вернуться можно через уведомление LocalLS. Не закрывайте проводник,
не смахивайте приложение из списка задач и не нажимайте «Остановить» в
системных настройках: уничтожение экрана передачи отменяет её очередь.
Активная передача использует foreground-уведомление. Уведомление сворачивания
без передачи не гарантирует бесконечную работу процесса.
Если телефон останавливает передачи с выключенным экраном, проверьте
разрешения уведомлений и ограничения батареи для LocalLS и серверного Termux.

9. ПОДГОТОВКА НОВОГО СЕРВЕРА НА ЭТОМ ТЕЛЕФОНЕ

Этот раздел выполняется на телефоне, который будет сервером.
1) Установите LocalLS и официальный Termux с F-Droid на этот телефон.
2) Откройте Termux один раз и дождитесь подготовки его среды. Вернитесь
   в LocalLS. Вводить команды для самого мастера не требуется.
3) Откройте «Настройки → Этот телефон — сервер» либо серверные инструменты
   и «Мастер настройки».
4) Нажмите «Выбрать папку Termux». В системном выборе откройте раздел
   Termux и выберите его корневую папку, затем разрешите доступ.
5) Разрешите LocalLS запуск команд Termux, когда Android попросит разрешение.
6) На совершенно новом сервере отметьте «Задать новый пароль сервера»
   и введите свой пароль дважды. На уже настроенном сервере оставьте
   переключатель выключенным, чтобы сохранить действующий пароль.
7) Нажмите «Подготовить сервер». Для первой установки OpenSSH нужен интернет.
8) Если откроется Termux для применения разрешения внешних команд,
   подождите несколько секунд и вернитесь кнопкой Android «Назад».
9) После успешной подготовки выполните «Проверить SSH и пароль».
10) Проверьте фактический Wi-Fi IP и экспортируйте LocalLS-server.json.
Мастер сохраняет существующие конфигурацию, ключи и работающий sshd.
Он не добавляет ещё одну схему автозапуска. Если автозапуска на новом сервере
нет, после перезагрузки снова запустите подготовку через мастер.
Первичная удалённая настройка с другого телефона без доступа к серверу
не выполняется: LocalLS для этого мастера должен работать на самом сервере.

10. ERROR RUN COMMAND / ALLOW-EXTERNAL-APPS

Такое сообщение означает отказ Termux принять внешнюю команду, а не
успешную установку сервера. Используйте актуальную LocalLS 0.9.4.
1) Убедитесь, что официальный Termux установлен и уже открыт хотя бы раз.
2) Повторно выберите именно корневую папку раздела Termux в мастере.
3) Через «Помощь с доступом Termux» проверьте разрешение запуска команд
   в системных разрешениях LocalLS, если оно доступно в вашей версии Android.
4) Повторите подготовку. Когда откроется Termux, дождитесь применения
   настроек и вернитесь «Назад», а не мгновенно переключайте приложения.
5) Повторите проверку SSH. При продолжающемся отказе сохраните версию Termux,
   Android и числовой код ошибки; пароль и токен в отчёт не включайте.
Мастер сам записывает allow-external-apps=true, сохраняя другие настройки.
Если файл настроек Termux некорректен, мастер не перезаписывает его вслепую.
Ошибки обновления пакетов и установки OpenSSH требуют проверить интернет
серверного телефона и доступность репозитория Termux, затем повторить шаг.

11. ПРОФИЛЬ ПОДКЛЮЧЕНИЯ НА ДРУГОМ УСТРОЙСТВЕ

После реальной успешной SSH-проверки сохраните LocalLS-server.json на сервере.
Передайте его клиентскому телефону или ПК и выберите «Импорт профиля».
Сверьте отпечаток с серверным устройством и отдельно введите SSH-пароль.
Профиль не содержит пароль и токен агента. Windows LocalLS также понимает
этот формат. Изменившийся уже доверенный ключ при импорте блокируется.

12. VPN / TAILSCALE

1) Установите официальный Tailscale на сервере и на каждом клиенте.
2) Войдите в одну tailnet и выполните первые системные подтверждения VPN.
3) В LocalLS откройте отдельный раздел «VPN / Tailscale».
4) Введите Tailscale IP сервера вида 100.x.x.x либо его MagicDNS-имя.
5) Выберите VPN-маршрут и сохраните параметры. Порт и пользователь SSH
   остаются серверными; включённый VPN не меняет их автоматически.
6) Переключатель относится только к VPN этого телефона. Если команда
   не поддерживается клиентом Tailscale, включите его в самом Tailscale.
Статус другого VPN сам по себе не означает, что сервер доступен по Tailscale.
Для домашнего подключения выбирайте локальный профиль. При использовании
Tailscale exit node разрешите LAN access, если нужен доступ к домашней сети.
Вход и включение VPN на ПК и сервере выполняются отдельно на этих устройствах.

13. WI-FI И ОФОРМЛЕНИЕ

Меню «Wi-Fi этого телефона» меняет сеть телефона, на котором открыт LocalLS.
Введите SSID, пароль WPA2 либо выберите открытую сеть. На Android 11+
подтвердите добавление сети в системном окне; на Android 10 разрешите
сетевую рекомендацию; на Android 7–9 используйте системные настройки.
Android выбирает подключение. Если сеть не переключилась, откройте
«Системные настройки». Удалённый Wi-Fi другого телефона не меняется.
После смены Wi-Fi IP сервера может измениться — обновите профиль клиентов.
В «Оформлении» можно выбрать тему и форму значков функций. Форма внешнего
значка на рабочем столе определяется вашим Android launcher.

14. ЗАПУСК, ОСТАНОВКА И ПЕРЕЗАПУСК SSH

В серверном меню команды «Включить SSH», «Отключить SSH» и «Перезапустить SSH»
используют отдельный, заранее установленный серверный агент. Укажите его
порт, обычно 8787, и действующий токен; сохраните доступ и проверьте статус.
SSH-пароль и токен агента — разные значения. Мастер подготовки SSH не означает,
что независимый агент уже установлен. Его описание есть в папке исходников
android/realme-agent. Действующую схему запуска сервера менять не требуется.
При остановке/перезапуске SSH дождитесь завершения передач и подтвердите команду.
Команды относятся к службе SSH, а не к перезагрузке или выключению телефона.
Агент остаётся отдельным каналом, через который можно снова запустить SSH.
Не публикуйте токен и не открывайте порт агента в публичный интернет;
для доступа извне используйте защищённую сеть Tailscale.

15. ЕСЛИ ЧТО-ТО НЕ РАБОТАЕТ

Не удаётся подключиться: проверьте актуальный IP, порт, работающий sshd,
маршрут Local/VPN, Wi-Fi и отсутствие изоляции клиентов в гостевой сети.
Неверный пароль: проверьте имя пользователя и SSH-пароль, а не пароль Wi-Fi.
Отказ SFTP: проверьте доступ пользователя к папке; системные каталоги
Android не становятся доступны автоматически через Termux.
Не скачивается: выберите разрешённую папку, проверьте свободное место
на телефоне и файл на сервере, затем повторите передачу.
Скачивание не открывает файл: найдите результат в выбранной папке телефона;
открытие содержимого файла выполняется подходящим установленным приложением.
Ошибка fingerprint: сначала установите причину смены ключа, затем сверяйте ключ.
Зависание при выключенном экране: проверьте батарею и разрешения обоих устройств.
Для обращения за помощью укажите версии приложения/Android/Termux, действие,
обычное сообщение и числовой код. Не присылайте пароль, токен или приватный ключ.
