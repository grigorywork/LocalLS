БЕЗОПАСНОСТЬ В ЭТОМ ОБНОВЛЕНИИ (9 октября 2026)

LocalLS теперь умеет входить по приватному SSH-ключу. Ключ пользователя
и SSH host key сервера — разные вещи: первый разрешает вход, второй помогает
проверить, что вы подключаетесь к известному серверу.

ПЕРЕХОД С ПАРОЛЯ БЕЗ ПОТЕРИ ДОСТУПА
1. Обновите приложение поверх прежней версии. Не удаляйте данные приложения.
2. Подключитесь прежним способом и сверьте SSH fingerprint с сервером.
3. Откройте Настройки → Безопасность / SSH-ключ. На Android пункт находится
   внутри настроек приложения. Создайте RSA 3072 или импортируйте свой ключ.
4. Для Windows/Fedora сначала включите «Сохранить секреты» в «Подключение»
   и сохраните настройки. Это доступно только при работающем системном
   шифровании. Без этой опции созданный ключ живёт только до полного выхода.
   При недоступной связке ключей используйте импорт имеющегося ключа,
   исходный файл храните отдельно, защищайте парольной фразой и правами доступа.
   Android сохраняет ключ зашифрованным средствами Android Keystore.
5. В разделе безопасности введите действующий пароль в поле установки ключа.
   Нажмите «Установить ключ и проверить вход» и подтвердите адрес/пользователя.
6. Приложение добавит только публичную часть в ~/.ssh/authorized_keys,
   сохранит существующие строки, выставит .ssh 700 и authorized_keys 600.
   Оно выполнит новое соединение только по ключу. Лишь после успеха клиент
   переключается на ключ и удаляет сохранённый пароль текущего профиля.
7. Подключитесь заново, откройте SFTP и проверьте передачу файла.
8. Повторите на каждом устройстве. Лучше иметь отдельный ключ для каждого
   устройства: потерянный ключ можно отозвать отдельно на сервере.
9. Проверьте вход после полного выхода/повторного запуска приложения.
   Парольный режим сервера не отключайте до этой проверки и подготовки
   резервного доступа на самом серверном устройстве.

В режиме ключа неверный/потерянный ключ вызывает ошибку. Приложение
не пытается незаметно использовать пароль. Режим пароля можно выбрать
вручную для миграции, если сервер ещё разрешает такой вход.
Экспорт .pub содержит только публичный ключ. Экспорт профиля не переносит
приватный ключ, парольную фразу, пароль или токен. На другом устройстве
нужно создать/импортировать свой ключ и разрешить его на сервере.
Удаление локального ключа не отзывает ключ на сервере: для отзыва удалите
соответствующую строку authorized_keys, сохранив остальные ключи.
Удаление приложения/сброс данных Android может уничтожить ключ Keystore;
перед этим обеспечьте другой проверенный способ доступа. Экспорт приватного
ключа из приложения в этой версии не реализован.

УПРАВЛЯЮЩИЙ АГЕНТ: HTTPS
Обычный SSH/SFTP не требует агента. Агент нужен для Start/Stop/Restart SSH,
в том числе когда SSH уже остановлен. Это независимый канал управления.
Новая версия агента 0.3 использует TLS 1.2+ и случайный Bearer-токен.
Скачайте отдельно LocalLS-Agent-0.3.zip из нового релиза; распакуйте на
серверном устройстве. Сохраните резервную копию прежней конфигурации.
На сервере в Termux выполните ./install.sh из этой папки. Установщик
сохраняет существующие токен, адрес, порт и схему автозапуска, создаёт
сертификат RSA 3072 и выводит его SHA-256. Токен показан только владельцу;
не отправляйте этот вывод в публичные логи/issue/чат.
Работающий старый процесс не перезапускается установщиком: завершите именно
этот процесс агента прежним способом и запустите обновлённый вручную.
Не запускайте второй агент поверх занятого порта и не трогайте работающий sshd.
В LocalLS укажите прежний порт и токен. В «Безопасность» нажмите проверку
HTTPS-сертификата агента, сравните SHA-256 с сервером и подтвердите.
Во время получения сертификата токен не отправляется. До доверия запросы
заблокированы; при смене сертификата они также блокируются. Подтверждайте
новый отпечаток только после независимой проверки на сервере.
Сертификат действует 365 дней; обновляйте его заранее и проверяйте новый pin.
Самоподписанный сертификат здесь доверяется по точному отпечатку, а не
просто потому, что сеть названа домашней. Первое подтверждение — ваша проверка.
Старый HTTP-агент работает только при явном включении временной совместимости.
Тогда токен передаётся без TLS, и приложение требует подтверждение действий.
По умолчанию этот режим выключен. Для нового агента оставьте его выключенным.

ПАРОЛЬНЫЙ ВХОД НА СЕРВЕРЕ
Это обновление НЕ отключает его автоматически и не меняет sshd_config,
порт SSH или механизмы запуска sshd. Клиентский вход только по ключу
не означает, что другой клиент больше не может войти на сервер по паролю.
После проверки всех ключей администратор может отдельно запретить пароль:
  PubkeyAuthentication yes
  PasswordAuthentication no
  KbdInteractiveAuthentication no
  AuthenticationMethods publickey
На Termux конфигурация обычно $PREFIX/etc/ssh/sshd_config; на Fedora —
/etc/ssh/sshd_config и включаемые файлы. Нужна проверка Include/Match,
резервная копия и проверка синтаксиса sshd -t перед применением.
Проверьте эффективные параметры sshd -T для нужного пользователя/адреса;
перезапустите службу штатным существующим способом при доступном резервном
сеансе и проверьте новое независимое подключение. Root/админ-права нужны
только там, где этого требует серверная ОС. Не копируйте настройки вслепую.

СЕТЬ И ИНТЕРНЕТ
Интернет на сервере для обновлений не означает доступ к нему из интернета.
Порт 8022 вместо 22 уменьшает часть шума, но не заменяет ключи и firewall.
Не делайте проброс SSH/агента на роутере, проверьте UPnP и правила IPv6:
IPv6 не обязательно защищён NAT. Для удалённого доступа используйте Tailscale
с ограниченными grants/ACL, проверенными устройствами и защищённым аккаунтом.
Открытие SSH через мастер Fedora разрешает сервис в текущей firewall-зоне;
это не автоматически ограничивает доступ только вашей домашней подсетью.
Проверьте зону/интерфейс/разрешённые источники средствами Fedora.
Отсутствие публичной доступности вашего сервера не проверено из этой среды.
Не публикуйте приватные ключи, токены, личные профили или конфигурацию агента.

1. КОМПЛЕКТ И УСТАНОВКА
В архиве LocalLS-Fedora-0.1.1-with-guides.zip находится папка Fedora:
  LocalLS-0.1.1-Fedora-x86_64.rpm — настоящий установочный пакет;
  INSTRUCTIONS_RU.txt — эта инструкция;
  INSTRUCTIONS_EN.txt — инструкция на английском;
  BUILD_REPORT.md — фактически выполненные проверки;
  SHA256SUMS.txt — контрольные суммы файлов.
Распакуйте архив. Инструкции можно открыть в любом текстовом редакторе
и в Блокноте Windows; кодировка UTF-8 с BOM.
Откройте RPM через приложение установки пакетов Fedora, если оно
поддерживает локальные RPM, и подтвердите установку паролем администратора.
Если графический установщик не принимает локальный RPM, используйте:
  sudo dnf install ./LocalLS-0.1.1-Fedora-x86_64.rpm
Команду выполняют в папке, куда скачан RPM. Зависимости установит DNF.
После установки найдите LocalLS в меню приложений Fedora.
RPM пока не подписан ключом издателя; контрольная сумма не заменяет подпись.
Пакет распространяется в GitHub Releases, а не в официальном репозитории Fedora.
Подготовка сервера из самого LocalLS не требует ввода команд в терминале.
Не запускайте всё приложение через sudo и не отключайте sandbox Electron.

Системные требования:
  Intel/AMD x86_64; графическая Fedora с polkit и штатным systemd/DNF.
  Рабочее подключение к сети; интернет нужен для установки пакетов.
  Для настройки сервера нужны права администратора Fedora.
  Для сохранения паролей нужна доступная и разблокированная связка ключей.
Сборка, установка RPM и графические тесты выполнены в Fedora 44 в контейнере.
Физический рабочий стол GNOME/Wayland или KDE пока не проверен.
Мастер DNF не предназначен для Fedora Silverblue/Kinoite/Atomic.
На других выпусках Fedora совместимость пока не подтверждена.

2. ПЕРВОЕ ПОДКЛЮЧЕНИЕ К СУЩЕСТВУЮЩЕМУ СЕРВЕРУ
Откройте «Подключение» в правом боковом меню.
Введите адрес сервера в локальной сети, порт, имя пользователя и папку.
Для обычного Fedora OpenSSH порт по умолчанию 22.
Для вашего существующего Termux/OpenSSH-сервера обычно порт 8022.
Имя пользователя берите из действующей учётной записи именно этого сервера.
Папка «.» означает домашнюю папку после SSH-входа.
Введите пароль сервера и нажмите «Сохранить», затем «Подключиться».
При первом подключении LocalLS покажет отпечаток SSH-ключа.
Сверьте его с вашим сервером или доверенным экспортированным профилем.
Подтверждайте только известный сервер. До проверки ключа пароль не отправляется.
Изменившийся ключ блокирует вход. Не забывайте ключ только ради обхода ошибки:
сначала выясните, была ли переустановка сервера или подмена адреса.
Для штатного сброса используйте «Забыть доверенный SSH-ключ» после проверки.
Отключение выполняется кнопкой «Отключиться».

3. ИМПОРТ И ЭКСПОРТ ПРОФИЛЯ
В «Подключение» доступны кнопки «Импорт профиля» и «Экспорт».
Формат localls-server-v1 совместим с LocalLS Android и Windows.
Профиль содержит адрес, порт, пользователя, папку и отпечаток ключа.
Пароли и токены в профиль не включаются; вводите пароль на принимающем устройстве.
Импортированный отпечаток требует подтверждения доверия.
Профиль всё равно содержит сведения о вашей сети, поэтому передавайте его
нужному человеку напрямую и не публикуйте личные профили в открытом репозитории.

4. ФАЙЛЫ И ПАПКИ
Откройте раздел «Файлы». Одна панель локальная, другая — серверная.
Двойной щелчок по папке открывает её; кнопка вверх возвращает в родительскую.
Поле пути позволяет перейти к нужной доступной папке сервера.
«Выбрать папку» задаёт рабочую локальную папку через системный выбор.
Права доступа остаются правами вашего пользователя, root-доступ не добавляется.
Один щелчок выделяет файл; повторный снимает выделение.
Можно выделять файлы в разных папках сервера: выделение сохраняется при навигации.
Нажмите «Скачать» и выберите любую доступную вам папку назначения.
Файлы с совпадающими именами при скачивании получают числовой суффикс.
Уже существующие локальные файлы автоматически не перезаписываются.
Для отправки выберите локальные файлы или нажмите кнопку прикрепления.
Прикреплённые файлы сначала появляются в списке; отправка начинается по кнопке.
Перед отправкой перейдите в нужную серверную папку: это папка назначения.
Замена существующего серверного файла требует отдельного подтверждения.
Можно создавать папки, переименовывать и удалять файлы.
Удаление и переименование требуют подтверждения; удаляются только пустые папки.
Рекурсивная передача целой папки и встроенный редактор в этой версии отсутствуют.
Чтобы передать много вложенных данных одним файлом, подготовьте архив отдельно.

5. ПЕРЕДАЧИ, ГРАФИК И ФОНОВАЯ РАБОТА
Раздел «Передачи» показывает очередь, прогресс и завершённые операции.
График строится по измеренной скорости текущих передач SFTP.
При отсутствии передач скорость равна нулю, это не тест пропускной способности.
Во время активной передачи можно свернуть окно и продолжить работу на компьютере.
Кнопка «Свернуть в фон» и закрытие окна сворачивают его, а не прекращают передачу.
В GNOME возвращайтесь через обзор приложений или снова запустите LocalLS из меню.
В среде с поддержкой трея доступен дополнительный значок LocalLS.
Расширение AppIndicator не требуется для возможности вернуть окно.
Для полного выхода нажмите «Выйти из LocalLS» в настройках либо пункт трея.
Если передача идёт, приложение попросит подтвердить её прерывание.
Выключение, выход из сеанса и потеря сети останавливают приложение/соединение.
Приложение не является постоянно работающей системной службой клиента.
История сохраняется локально; после повторного запуска видны завершённые записи.
Автоматического возобновления незавершённой передачи после перезапуска пока нет.

6. СДЕЛАТЬ ЭТОТ КОМПЬЮТЕР СЕРВЕРОМ
Мастер относится к компьютеру, на котором сейчас запущен LocalLS.
Откройте «Настройки» → «Этот компьютер — сервер».
Статус показывает наличие OpenSSH, состояние sshd.service, автозапуск,
текущего пользователя Fedora и доступные IPv4-адреса.
Нажмите «Установить OpenSSH», если пакет отсутствует.
LocalLS вызовет штатный DNF; системное окно polkit запросит администратора.
Пакет openssh-server устанавливается без замены вашей SSH-конфигурации.
Нажмите «Запустить SSH». Используется существующая служба sshd.service.
Не создаётся второй sshd, отдельный агент или конкурирующий автозапуск.
Если хотите запуск сервера после включения ПК, нажмите «Включить автозапуск».
Для обратного действия есть «Убрать автозапуск».
«Перезапустить SSH» перезапускает службу, а не перезагружает компьютер.
Перезапуск может разорвать существующие SSH-сеансы.
«Остановить SSH» прекращает доступ; это не выключение питания компьютера.
Установка LocalLS сама по себе не запускает сервер и не открывает порт.
Каждая административная операция требует вашего подтверждения и polkit.
Отмена подтверждения не считается успешным выполнением операции.

Вход на Fedora использует существующий пароль вашей учётной записи ОС.
Пароль не создаётся и не заменяется приложением.
Кнопка «Пароль учётной записи» открывает системные настройки пользователей.
Если пароль не задан или вход по паролю запрещён настройками вашего SSH,
настройте учётную запись/политику сервера средствами Fedora.
Мастер проверки локального сервера использует пароль; обычный клиент поддерживает SSH-ключи через раздел «Безопасность».

Проверка и экспорт:
  1) Введите фактический SSH-порт этого сервера: обычно 22.
  2) Введите пароль своей учётной записи Fedora для проверки.
  3) Нажмите «Проверить SSH-вход» и подтвердите показанный отпечаток.
  4) LocalLS реально подключается к 127.0.0.1 и проверяет SFTP-доступ.
  5) Поле пароля очищается, пароль проверки не сохраняется.
  6) Выберите IPv4-адрес для другого устройства и экспортируйте профиль.
Экспорт становится доступен только после успешной проверки входа.
Проверка на 127.0.0.1 подтверждает службу и пароль, но не доступ через роутер:
после импорта профиля обязательно проверьте подключение со второго устройства.
Для локального адреса второй телефон/ПК должен иметь сетевой доступ к Fedora.
После смены Wi-Fi обновите статус и экспортируйте профиль с новым адресом.

7. FIREWALL И ПОРТ
«Разрешить SSH:22» добавляет стандартную службу ssh в firewalld:
в текущие правила и в постоянную конфигурацию зоны по умолчанию.
«Закрыть SSH:22» удаляет это стандартное разрешение из той же зоны.
Эти кнопки не меняют SSH-порт и не создают правило для произвольного порта.
Если интерфейс сети привязан к другой зоне, измените её правила средствами ОС.
Если сервер уже использует нестандартный порт, введите его для проверки,
а firewall настройте штатными средствами Fedora; рабочий sshd_config сохраняется.
Если firewalld отсутствует или не работает, операция покажет ошибку.
LocalLS не включает firewall автоматически и не сбрасывает его настройки.
При подключении извне рекомендуется Tailscale вместо проброса порта на роутере.

8. VPN / TAILSCALE
Откройте отдельный пункт «VPN / Tailscale».
Нужен официальный Tailscale на этом компьютере и на сервере/втором устройстве.
«Открыть / установить Tailscale» открывает официальный сайт установки Linux
либо официальный адрес входа, если установленный клиент уже требует авторизацию.
Установку Tailscale и вход в аккаунт выполняйте по инструкции поставщика.
Переключатель выполняет tailscale up/down с системным подтверждением polkit.
При первом входе может понадобиться браузер: нажмите «Открыть / установить».
Ожидание первоначального входа ограничено; без авторизации соединение не включится.
Нажмите «Обновить статус» после входа. Статус берётся из реального клиента.
Введите Tailscale IP 100.x.x.x или MagicDNS сервера, выберите VPN-маршрут
и сохраните настройки. Он используется при следующем SSH-подключении.
Отключитесь и подключитесь снова после смены маршрута.
Устройства должны быть в вашей tailnet и иметь разрешение доступа по ACL.
LocalLS не предоставляет свой VPN-сервис и не обходит ограничения Tailscale.
Локальный Wi-Fi при этом остаётся доступным; IP локального сервера не подменяется.

9. WI-FI И ВНЕШНИЙ ВИД
«Настройки» → «Wi-Fi этого компьютера» открывает системные настройки сети
GNOME либо KDE. Сеть и пароль вводятся в окне ОС, не в журналах LocalLS.
Это меняет сеть текущего компьютера, а не удалённого сервера на другом устройстве.
Если системный модуль не найден, откройте Wi-Fi через стандартное меню Fedora.
При смене сети соединение может оборваться; подключитесь заново.
В настройках есть темы: фиолетовая светлая/тёмная, океан, лес, янтарь.
Форма кнопок с иконками: скруглённая, квадратная, круглая.
Нажмите «Сохранить», чтобы изменения сохранились после выхода.

10. СОХРАНЕНИЕ ПАРОЛЕЙ И ОШИБКИ
Секреты сохраняются только через доступное системное шифрование Electron.
При недоступной/закрытой связке ключей сохранение отключается;
пароль остаётся в памяти до закрытия приложения, а не в открытом TXT/JSON.
Отпечатки ключей и параметры подключения сохраняются без пароля.
На чужом компьютере не включайте запоминание пароля.
«Сервер отклонил вход»: проверьте пользователя, пароль и политику SSH сервера.
«SSH-порт недоступен»: проверьте запуск SSH, IP, порт, firewall и сеть.
«Нет доступа»: выберите папку, разрешённую вашей учётной записи.
«Системная операция не выполнена»: проверьте polkit, состояние службы,
доступ к интернету для DNF и наличие firewalld/Tailscale для их операций.
Не отправляйте пароль, токен, приватный ключ или личный профиль в открытый issue.
Для отчёта достаточно версии Fedora/LocalLS, действия и обезличенного текста ошибки.

11. УДАЛЁННОЕ УПРАВЛЕНИЕ И ГРАНИЦЫ ВЕРСИИ
Пункт «Управление сервером» относится к уже установленному независимому агенту
на удалённом сервере. Для него нужны адрес/порт агента и его собственный токен.
Обычное SSH/SFTP-подключение не требует этого агента.
Мастер Fedora управляет локальным systemd напрямую и агент для него не нужен.
Выключение/включение питания удалённого телефона или ПК не реализовано.
Полный тест полkit, физического GNOME/Wayland, Wi-Fi и VPN-аккаунта в контейнере
невозможен; эти ограничения прямо указаны в BUILD_REPORT.md.
Android и Windows опубликованы отдельно и их рабочие сборки сохранены.
