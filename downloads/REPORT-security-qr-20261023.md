# LocalLS — проверка безопасности и постоянная QR-привязка, 23 октября 2026

Версия 0.11.21 / code 41, package com.bitpoint.homeservercontrol. Ветка release/android-0.11.21 не менялась. Все прежние локальные изменения сохранены; новый release/versionCode не создавался.

## Что исправлено

- При восстановлении экрана с действующим QR уже подтверждённая привязка ошибочно начинала обмен повторно. Теперь успешный вход сохраняет публичную отметку, связанную с точными host/port/user, pin сервера и публичным ключом клиента. Временный nonce/срок QR не ограничивают сохранённый доступ. Восстановленный экран открывает сохранённую привязку даже при выключенном сервере, без нового сканирования и без повторного разрешения владельца.
- Незавершённый обмен раньше терялся при закрытии клиента. Публичное приглашение сохраняется до завершения/истечения срока; при открытии используется тот же ключ и тот же код сверки, а одобрение на сервере остаётся обязательным. Успешная привязка очищает временное приглашение. Смена профиля/pin/ключа не наследует чужую отметку. Сервер проверяет владение закрытым ключом при каждом SSH-входе; отметка в UI сама по себе доступа не даёт.
- QR принимает только плоские поля протокола. Вложенные JSON и нестандартные комментарии отсекаются до рекурсивного парсера, чтобы недоверенный payload не мог исчерпать стек. PIN/время/nonce/точный код сверки и запрет замены уже разрешённого ключа сохранены.
- Нажатие на путь телефона, а также «Выше» в корне, открывает системный выбор любой доступной Android папки: внутренняя память, SD/USB и провайдеры документов. Выбранная папка, её название и разрешение чтения/записи сохраняются. Папку только для чтения теперь можно просматривать и отправлять; приём, создание, переименование и удаление в ней блокируются. Папка просмотра хранится отдельно от прежней writable destination сервиса передачи, и read-only выбор не подменяет эту папку приёма. Отмена выбора сохраняет прежнюю папку; выбор «Загрузки» также переживает перезапуск. Папка автоприёма сервера не меняется этим выбором.
- На главной самого телефона-сервера компактно видны Wi-Fi адрес, фактический порт/состояние службы и статус доступа по ключу. Клиентские элементы остаются скрыты. Проверены узкие экраны, обе ориентации и крупный шрифт; все кнопки сохранены.

## Имитация атак

Все подключения выполнены только к одноразовым SSH-серверам на 127.0.0.1, без воздействия на телефоны или внешние серверы. Полный набор включает:

| Попытка | Результат |
|---|---|
| Вход с паролем, неверным пользователем, неизвестным ключом | Отклонён |
| Копия разрешённого публичного ключа с подписью чужого приватного ключа, обычный и QR username | Поддельная подпись реально отправлена; вход отклонён |
| Сервер с другим pin | Отклонён до предложения ключа клиента |
| Неверный/просроченный/обновлённый nonce, повтор старого QR | Не даёт доступа |
| Второй клиент пытается заменить уже разрешённый ключ | Отклонён; прежний доступ сохранён |
| 12 последовательных входов чужим ключом | Отклонены, файл и разрешённая идентичность не изменились; законный вход работает |
| Чтение за пределами раздачи, traversal, ссылки | Отклонено |
| Запись, удаление, rename и mkdir через ссылку наружу | Отклонено; внешние байты/пути и исходный файл проверены |
| Shell, exec, локальный/удалённый forwarding, hardlink/symlink | Отклонено |
| Слишком много сессий, остановка во время аутентификации | Лимиты/закрытие проверены без зависания |
| Подмена полей QR, вложенный payload, запоздавшие callbacks | Отказ или игнорирование без изменения сохранённых ключей |

В проверенных сценариях обход авторизации не получен. Это ограниченный автоматизированный аудит, а не гарантия отсутствия всех уязвимостей и не нагрузочный DDoS-тест. QR передаёт публичные данные; приватный ключ остаётся на своём телефоне. Первое локальное одобрение нового телефона обязательно. Обновление QR не отменяет уже сохранённый разрешённый ключ; отзыв на сервере блокирует фактический SSH-доступ.
