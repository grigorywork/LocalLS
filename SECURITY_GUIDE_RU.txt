БЕЗОПАСНОСТЬ В ЭТОМ ОБНОВЛЕНИИ (9 октября 2026)

LocalLS теперь умеет входить по приватному SSH-ключу. Ключ пользователя
и SSH host key сервера — разные вещи: первый разрешает вход, второй помогает
проверить, что вы подключаетесь к известному серверу.

ПЕРЕХОД С ПАРОЛЯ БЕЗ ПОТЕРИ ДОСТУПА
1. Обновите приложение поверх прежней версии. Не удаляйте данные приложения.
2. Подключитесь прежним способом и сверьте SSH fingerprint с сервером.
3. Откройте Настройки → Безопасность / SSH-ключ. На Android пункт находится
   внутри настроек приложения. Создайте RSA 3072 или импортируйте свой ключ.
4. Для Windows/Fedora сначала включите «Сохранить секреты» в «Подключение»
   и сохраните настройки. Это доступно только при работающем системном
   шифровании. Без этой опции созданный ключ живёт только до полного выхода.
   При недоступной связке ключей используйте импорт имеющегося ключа,
   исходный файл храните отдельно, защищайте парольной фразой и правами доступа.
   Android сохраняет ключ зашифрованным средствами Android Keystore.
5. В разделе безопасности введите действующий пароль в поле установки ключа.
   Нажмите «Установить ключ и проверить вход» и подтвердите адрес/пользователя.
6. Приложение добавит только публичную часть в ~/.ssh/authorized_keys,
   сохранит существующие строки, выставит .ssh 700 и authorized_keys 600.
   Оно выполнит новое соединение только по ключу. Лишь после успеха клиент
   переключается на ключ и удаляет сохранённый пароль текущего профиля.
7. Подключитесь заново, откройте SFTP и проверьте передачу файла.
8. Повторите на каждом устройстве. Лучше иметь отдельный ключ для каждого
   устройства: потерянный ключ можно отозвать отдельно на сервере.
9. Проверьте вход после полного выхода/повторного запуска приложения.
   Парольный режим сервера не отключайте до этой проверки и подготовки
   резервного доступа на самом серверном устройстве.

В режиме ключа неверный/потерянный ключ вызывает ошибку. Приложение
не пытается незаметно использовать пароль. Режим пароля можно выбрать
вручную для миграции, если сервер ещё разрешает такой вход.
Экспорт .pub содержит только публичный ключ. Экспорт профиля не переносит
приватный ключ, парольную фразу, пароль или токен. На другом устройстве
нужно создать/импортировать свой ключ и разрешить его на сервере.
Удаление локального ключа не отзывает ключ на сервере: для отзыва удалите
соответствующую строку authorized_keys, сохранив остальные ключи.
Удаление приложения/сброс данных Android может уничтожить ключ Keystore;
перед этим обеспечьте другой проверенный способ доступа. Экспорт приватного
ключа из приложения в этой версии не реализован.

УПРАВЛЯЮЩИЙ АГЕНТ: HTTPS
Обычный SSH/SFTP не требует агента. Агент нужен для Start/Stop/Restart SSH,
в том числе когда SSH уже остановлен. Это независимый канал управления.
Новая версия агента 0.3 использует TLS 1.2+ и случайный Bearer-токен.
Скачайте отдельно LocalLS-Agent-0.3.zip из нового релиза; распакуйте на
серверном устройстве. Сохраните резервную копию прежней конфигурации.
На сервере в Termux выполните ./install.sh из этой папки. Установщик
сохраняет существующие токен, адрес, порт и схему автозапуска, создаёт
сертификат RSA 3072 и выводит его SHA-256. Токен показан только владельцу;
не отправляйте этот вывод в публичные логи/issue/чат.
Работающий старый процесс не перезапускается установщиком: завершите именно
этот процесс агента прежним способом и запустите обновлённый вручную.
Не запускайте второй агент поверх занятого порта и не трогайте работающий sshd.
В LocalLS укажите прежний порт и токен. В «Безопасность» нажмите проверку
HTTPS-сертификата агента, сравните SHA-256 с сервером и подтвердите.
Во время получения сертификата токен не отправляется. До доверия запросы
заблокированы; при смене сертификата они также блокируются. Подтверждайте
новый отпечаток только после независимой проверки на сервере.
Сертификат действует 365 дней; обновляйте его заранее и проверяйте новый pin.
Самоподписанный сертификат здесь доверяется по точному отпечатку, а не
просто потому, что сеть названа домашней. Первое подтверждение — ваша проверка.
Старый HTTP-агент работает только при явном включении временной совместимости.
Тогда токен передаётся без TLS, и приложение требует подтверждение действий.
По умолчанию этот режим выключен. Для нового агента оставьте его выключенным.

ПАРОЛЬНЫЙ ВХОД НА СЕРВЕРЕ
Это обновление НЕ отключает его автоматически и не меняет sshd_config,
порт SSH или механизмы запуска sshd. Клиентский вход только по ключу
не означает, что другой клиент больше не может войти на сервер по паролю.
После проверки всех ключей администратор может отдельно запретить пароль:
  PubkeyAuthentication yes
  PasswordAuthentication no
  KbdInteractiveAuthentication no
  AuthenticationMethods publickey
На Termux конфигурация обычно $PREFIX/etc/ssh/sshd_config; на Fedora —
/etc/ssh/sshd_config и включаемые файлы. Нужна проверка Include/Match,
резервная копия и проверка синтаксиса sshd -t перед применением.
Проверьте эффективные параметры sshd -T для нужного пользователя/адреса;
перезапустите службу штатным существующим способом при доступном резервном
сеансе и проверьте новое независимое подключение. Root/админ-права нужны
только там, где этого требует серверная ОС. Не копируйте настройки вслепую.

СЕТЬ И ИНТЕРНЕТ
Интернет на сервере для обновлений не означает доступ к нему из интернета.
Порт 8022 вместо 22 уменьшает часть шума, но не заменяет ключи и firewall.
Не делайте проброс SSH/агента на роутере, проверьте UPnP и правила IPv6:
IPv6 не обязательно защищён NAT. Для удалённого доступа используйте Tailscale
с ограниченными grants/ACL, проверенными устройствами и защищённым аккаунтом.
Открытие SSH через мастер Fedora разрешает сервис в текущей firewall-зоне;
это не автоматически ограничивает доступ только вашей домашней подсетью.
Проверьте зону/интерфейс/разрешённые источники средствами Fedora.
Отсутствие публичной доступности вашего сервера не проверено из этой среды.
Не публикуйте приватные ключи, токены, личные профили или конфигурацию агента.
