# LocalLS Android 0.11.12 — разные IP и сохранение доступа

LocalLS Android 0.11.12 — проверка разных IP и исправление смены адреса.

- Исправлено сохранение нового IP через «Сеть»: ключ доступа и проверенный fingerprint того же сервера теперь переносятся так же, как через главный экран. Повторно создавать ключ и передавать .pub не нужно. Конфликтующие сохранённые ключи и отпечатки не заменяются.
- Неверный IP больше не перезаписывает рабочее подключение. VPN-профиль можно сохранить без выдуманного локального адреса.
- Уточнена подсказка: в подключении нужен IP другого телефона-сервера. При недоступном порте проверяются запуск сервера, его актуальный адрес и обмен между устройствами Wi-Fi. Открытый TCP-порт не выдаётся за успешную авторизацию.
- Компактный вид IP без крупной рамки и кнопки копирования сохранён.

Проверено на стенде: настоящие TCP/SSH/SFTP-соединения с разными адресами источника и сервера; передача и скачивание 60 МиБ с проверкой SHA-256; папка и пустая вложенная папка; две последовательные смены IP через «Сеть» и главный экран с прежними ключами; независимый OpenSSH/SFTP-клиент с отдельным исходным IP. Адреса стенда — loopback, это не проверка Wi-Fi-радио и не настройка вашего роутера.

Оба телефона подключи к одной обычной сети Wi-Fi с разрешённым обменом устройств. На телефоне 1 включи сервер и посмотри его IP. На телефоне 2 введи IP телефона 1 в существующем подключении, оставь порт и пользователя, сохрани и нажми «Проверить SSH». Разные собственные IP телефонов нормальны. Гостевая сеть или изоляция клиентов может блокировать соединение даже при одинаковом имени Wi-Fi; приложение не может отменить запрет роутера.

Установи поверх 0.11.11 на оба телефона без удаления и очистки данных; затем включи сервер вручную. Прежний release-сертификат, versionCode 32 > 31.

[Инструкция](https://github.com/grigorywork/LocalLS/blob/android-v0.11.12/android/app/src/main/assets/phone-setup.txt) обновлена и встроена в APK.

120 JVM-тестов и 7 Python-тестов прошли без ошибок и пропусков, lint без ошибок. Сборки release и instrumentation APK прошли. Физические телефоны не подключены, установка и испытание на реальном Wi-Fi не выполнялись. Остальные ограничения фоновой работы, восстановления очереди и повторного копирования папок сохраняются.


Проверки: JVM {'tests': 120, 'failures': 0, 'errors': 0, 'skipped': 0}, Lint {'Error': 0, 'Warning': 26}, Python 7 тестов подписи и обновления. Статические аудиты проекта и архитектуры без ошибок; 85 production-классов / 5 модулей. Release и instrumentation APK собраны. ADB devices пуст, физические установки и instrumentation не выполнялись.

Воспроизведение: три новых сценария LanConnectionIntegrationTest сначала завершились ошибкой на production-коде 0.11.11 (reproduce.log): потеря маршрута к существующему ключу/pin при сохранении нового адреса через NetworkActivity, сохранение неправильного IPv4 999.1.1.1 поверх рабочего подключения, отказ сохранить VPN-only профиль с пустым локальным полем. Исправление проверено повторным целевым прогоном (lan-tests.log) и полным прогоном (verified-build.log). Четвёртый сценарий проверяет сохранность уже известного назначения с другой парой и pin.

Живой сетевой сценарий: сервер SFTP привязан к 127.0.0.2, производственный SftpClient.TreeSession подключается к нему с другого исходного адреса loopback. Реальный Socket проверяется на различие локального и удалённого адреса. Приложение создаёт папку и пустую вложенную папку, загружает 60 MiB, скачивает в другой файл. Сравниваются длина и SHA-256 источника, серверной копии и скачанной копии. Сервер перемещается на 127.0.0.3 на том же порту, с тем же host key, пользователем и разрешённой клиентской парой. Новый адрес сохраняется через настоящий экран «Сеть» в Robolectric; проверяются pin/ключ, SSH-вход и доступ к папке. Старый адрес больше не отвечает. Затем сервер перемещается на 127.0.0.4, адрес сохраняется на главном экране; снова подтверждается вход с прежней парой и pin. Настоящий Android Keystore в этом JVM-тесте заменён хранилищем в памяти, остальной путь настроек/криптографии/SSH/SFTP — production.

Независимая проверка: OpenSSH SFTP явно привязан параметром BindAddress к 127.0.0.5 и соединяется с сервером 127.0.0.2. Передаёт и скачивает 5 MiB + 31 байт с проверкой всех байтов; StrictHostKeyChecking=yes, заранее проверенный host key и IdentitiesOnly=yes, пароль не используется. Это реальные TCP-соединения разных IP одного loopback-пространства. Они не эмулируют Wi-Fi-радио, L2/AP-изоляцию, DHCP или реальную топологию роутера; успешность на конкретных телефонах из этого не следует.

Изменения NetworkActivity.save: адреса проверяются тем же ConnectionEndpoint, что на главном экране. Неактивный адрес может быть пустым; некорректный непустой адрес не сохраняется. Порт и пользователь берутся из сохранённого подключения и проверяются. Перед изменением активного адреса вызывается существующий SshKeys.moveRoute; исключение не заменяет старый профиль. Результат успешного переноса обозначается сообщением. Ранее экран «Сеть» менял только prefs IP/режима, оставляя пару и pin привязанными к прежнему IP.

Политика доверия не ослаблена: новый IP того же сервера наследует прежний pin; конфликтующая личность назначения не заменяется. При подмене SSH-ключа до авторизации соединение блокируется, это проверяется существующим тестом живого SSH-сервера. Сервер по-прежнему авторизует разрешённую пару, не предоставляет shell/forwarding и ограничивает файловую систему папкой LocalLS. Дополнительных разрешений, фонового сканирования, новых паролей и автоматического доверия не добавлено. Функция IP остаётся компактной строкой из 0.11.11.

Сообщения проверки уточнены: проверка TCP-порта на экране «Сеть» не объявляет авторизацию выполненной и направляет к полной проверке SSH. Отказ и таймаут предлагают проверить текущий адрес сервера и обмен устройств в Wi-Fi; таймаут не объявляется доказательством изоляции. В главной подсказке явно указан адрес другого телефона. При конфликте fingerprint сообщается блокирование авторизации и передачи файлов вместо устаревшего упоминания пароля.

Это не физическая установка. Приватный ключ APK находится вне репозитория и не публикуется. Windows/Fedora не менялись. Работа по последнему моду завершена; без нового запроса следующую ревизию не разрабатывать.
