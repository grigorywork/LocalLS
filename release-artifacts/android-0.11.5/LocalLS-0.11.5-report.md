# LocalLS Android 0.11.5 — экспорт принятого файла

LocalLS Android 0.11.5 — сохранение принятых файлов и цветные статусы.

На телефоне-сервере открой «Файлы сервера / сохранить на телефон», нажми на принятый файл и выбери «В Загрузки → LocalLS» (Android 10+). После зелёного сообщения копия доступна в системных «Файлы → Загрузки → LocalLS». Для Android 8–9 и другого места сохранения используется системный выбор документа.

- Прямое сохранение через MediaStore в Загрузки/LocalLS на Android 10+.
- Копирование выполняет foreground-служба с прогрессом и уведомлением. Закрытие экрана файлов не отменяет копию.
- Успех появляется после закрытия выходного потока и завершения публикации. Повреждённая/неполная новая запись MediaStore удаляется при обработанном сбое; выбранные пользователем документы автоматически не удаляются.
- Ошибки видны на красной плашке с кнопкой безопасной диагностики. Оригинал принятого файла остаётся в LocalLS.
- Работающий сервер выделен зелёным, ожидание и сохранение — жёлтым, ошибка — красным. Инструкция в APK обновлена.

[Инструкция](https://github.com/grigorywork/LocalLS/blob/android-v0.11.5/android/app/src/main/assets/phone-setup.txt). Прежняя release-подпись, versionCode 25, установка поверх 0.11.4. Подключение и принятые файлы не нужно сбрасывать. Физическое устройство в этой среде недоступно; публикация предварительная.

Проверки: JVM {'tests': 79, 'failures': 0, 'errors': 0, 'skipped': 0}; 7 Python-тестов правил обновления/подписи. Аудиты проекта и архитектуры: 0 ошибок. Lint: {'Error': 0, 'Warning': 18}. Android instrumentation APK собран; запуск на физическом устройстве не выполнялся.

Воспроизведённые дефекты прежнего кода: локальная копия запускалась на executor экрана и отменялась через shutdownNow() при уничтожении Activity; все исключения поглощались; success=true устанавливался до закрытия выходного потока, поэтому ошибка close могла неверно считаться успехом. По одному сообщению «Не удалось сохранить файл» нельзя установить точную причину отказа конкретного телефона. Новые диагностические этапы позволяют отличить SOURCE / DESTINATION / COPY / CLOSE / PUBLISH / FOREGROUND / STOPPED без вывода URI, имён файлов и сообщений исключений.

Тесты с файлом 60 MiB + 17 байт: потоковая копия с Unicode-именем и сравнением SHA-256; копия через ContentResolver/провайдер MediaStore в Robolectric, при этом Activity закрывается до разрешения записи, затем проверяются длина и SHA-256. Это тестовый провайдер на JVM, не проверка системного MediaStore на физическом Android. Также проверены отказ разрешений, исключение записи, сбой закрытия, сбой публикации, прерывание, изменение исходного файла при копировании, запрет выхода за папку и сохранность исходника.

MediaStore использует app-owned запись в Download/LocalLS с IS_PENDING=1; после закрытия потока публикация меняет IS_PENDING на 0. При обработанном сбое удаляется только созданная этой операцией запись. Выбранный SAF-документ не удаляется автоматически, поскольку провайдер может вернуть существующий документ. URI выбранного документа передаётся своей неэкспортируемой службе с временными URI-grant flags. Архитектура не является очередью с восстановлением после принудительного завершения процесса: START_NOT_STICKY, отдельная foreground-служба dataSync, ограниченная wake lock. Необработанное завершение процесса может оставить незавершённую запись провайдера; подтверждена устойчивость именно к закрытию экрана.

Цветные плашки содержат текстовое состояние, рамку и отдельный фон для светлой/тёмной темы. Работающий локальный сервер зелёный, ожидание первого разрешённого клиента жёлтое; остановка нейтральная, ошибка красная. Статусы удалённого подключения и локального экспорта оформлены аналогично. Ключи, папка исходных файлов и параметры подключения не менялись.
