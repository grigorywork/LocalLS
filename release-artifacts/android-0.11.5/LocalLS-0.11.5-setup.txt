LocalLS — настройка двух телефонов
Для версии 0.11.5 и новее

Телефон 1 — сервер: на него приходят файлы.
Телефон 2 — подключается к телефону 1 и отправляет файлы.

СНАЧАЛА — ТЕЛЕФОН 1

1. Установи одинаковую версию LocalLS на оба телефона. Подключи телефон 1 к Wi-Fi. Для первой проверки используй обычную домашнюю сеть.

2. На телефоне 1 открой «Мой сервер → Настроить сервер». Телефон 2 пока не настраивай.

3. В разделе «1. Настрой и включи сервер» оставь пользователя localls и порт 8022. Ниже приложение само покажет текущий адрес этого телефона: строку «IP: ...». Если адреса нет, подключись к Wi-Fi и вернись на этот экран. Если указаны несколько адресов, нужен адрес той Wi-Fi сети, к которой затем подключишь телефон 2.

4. При первой настройке поле «Разрешённый публичный ключ» пустое — так и оставь. Если настраиваешь пару заново и здесь уже есть старый ключ, сначала нажми «Остановить сервер», затем очисти это поле. Это отменит прежнее разрешение при следующем запуске; файлы и личность сервера не удаляются.

5. Нажми «Включить сервер». Разреши уведомления и доступ к локальной сети, если Android спросит. Дождись надписи «Сервер готов ... Ожидает телефон 2. Вход пока закрыт».

6. Данные для второго телефона уже находятся на этом экране: IP, порт, пользователь и fingerprint. Можно нажать «Скопировать данные подключения». Этот адрес не нужно придумывать или брать из старой инструкции.

ТЕПЕРЬ — ТЕЛЕФОН 2

7. Подключи телефон 2 к тому же Wi-Fi. Для первой проверки отключи VPN на обоих телефонах.

8. Открой LocalLS → «Подключение → Адрес и ключ». Выбери «Локально». В поле «Локальный IP» введи только адрес из строки «IP» телефона 1 — без sftp:// и без порта. Порт — 8022, пользователь — localls. Поле VPN оставь пустым. Нажми «Сохранить настройки».

9. Нажми «Ключ доступа». При первой настройке нажми «Создать ключ RSA 3072» и подтверди. При перенастройке создание нового ключа заменит прежний ключ текущего подключения.

10. Нажми «Экспортировать публичный ключ .pub». Сохрани файл как telefon2.pub. Передай этот файл телефону 1, например Bluetooth или сообщением как файл, и сохрани его на телефоне 1.

ОДНО ПОДТВЕРЖДЕНИЕ — НА ТЕЛЕФОНЕ 1

11. На открытом экране «Мой сервер» нажми «Добавить телефон 2 (.pub)». Выбери полученный telefon2.pub и нажми «Разрешить». Сервер, ожидающий первый телефон, не нужно перезапускать. Дождись статуса «Сервер работает ... Разрешён вход по добавленному ключу».

ПРОВЕРКА — НА ТЕЛЕФОНЕ 2

12. Нажми «Проверить SSH». При запросе доверия сверь fingerprint с телефоном 1. Подтверди только при совпадении. Пока ключ не добавлен на телефоне 1, статус доступного порта без авторизации ожидаем.

13. Открой «Файлы сервера». Папка может быть пустой. Затем выбери «Отправить файл», укажи небольшой файл и подтверди отправку.

14. На телефоне 1 открой «Файлы сервера / сохранить на телефон» и нажми «Обновить». Там должен появиться присланный файл с его размером. Нажми на имя файла и выбери сохранение в «Загрузки → LocalLS» (Android 10+). После зелёной надписи «Файл сохранён на телефон» ищи копию в системных «Файлы → Загрузки → LocalLS». Кнопка «Открыть «Загрузки»» поможет открыть системный список. Можно выбрать другое место через системное окно Android. На Android 8–9 используется выбор места сохранения.

Во время сохранения виден прогресс. Копирование продолжится при закрытии этого экрана; исходный файл остаётся внутри LocalLS. Если показана красная ошибка, нажми «Скопировать ошибку сохранения» и передай текст для проверки. Не удаляй исходный файл. Сервер предоставляет только папку LocalLS, а не весь телефон.

ЕСЛИ НЕ ПОЛУЧИЛОСЬ

Если телефон 1 не показывает адрес — проверь Wi-Fi. Если сервер не запускается — нажми «Скопировать диагностику запуска» и передай отчёт для проверки. Если телефон 2 видит порт, но не входит — проверь, что на телефоне 1 разрешён именно публичный ключ текущего подключения телефона 2.

IP может измениться после переподключения Wi-Fi. Тогда возьми новый адрес с телефона 1. Если после смены адреса LocalLS на телефоне 2 пишет, что ключ нового профиля отсутствует, настрой ключ для этого подключения и передай его публичную часть телефону 1; для замены уже разрешённого ключа сервер нужно остановить, импортировать новый .pub и запустить снова.

О БЕЗОПАСНОСТИ

До добавления ключа вход закрыт для всех. После разрешения нужен соответствующий закрытый ключ; одного публичного файла для входа недостаточно. Закрытая часть хранится внутри телефона 2 и никуда не пересылается. Парольный вход отключён. Отпечаток сервера проверяется отдельно от ключа телефона 2.

Для этой настройки не нужны Termux, открытие портов роутера или публикация сервера в интернете. Публичная инструкция не содержит адресов, ключей или настроек конкретного владельца. Адреса и ключи приложения автоматически на GitHub не отправляются.

Если настройка начинается не с пустого поля, ранее разрешённый ключ продолжает действовать до остановки и замены. Приложение не очищает его автоматически при обновлении. Android может ограничивать фоновую службу и время её работы; сервер запускается вручную, без автозапуска после перезагрузки.
