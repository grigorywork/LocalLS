# LocalLS Android 0.11.4 — последовательная настройка

LocalLS Android 0.11.4 — сначала телефон 1, потом телефон 2.

[Инструкция для двух телефонов](https://github.com/grigorywork/LocalLS/blob/android-v0.11.4/android/app/src/main/assets/phone-setup.txt). Она также входит в APK и открывается без интернета: «Мой сервер → Настроить сервер → Инструкция: два телефона».

- Телефон 1 сам показывает адрес Wi-Fi до запуска сервера; адрес не нужно искать в старой инструкции.
- При пустом разрешённом ключе сервер запускается в ожидании телефона 2. Порт открыт, но вход закрыт для всех ключей и паролей.
- Затем на телефоне 2 настраивается подключение и создаётся его ключ. Владелец выбирает публичный .pub на телефоне 1 и явно нажимает «Разрешить».
- Первый ключ добавляется к ожидающему серверу без перезапуска. Для замены уже разрешённого ключа сервер по-прежнему нужно остановить.
- Опубликована общая инструкция без персональных адресов, ключей и конфигурации владельца. Данные приложения автоматически на GitHub не отправляются.

versionCode 24, прежняя release-подпись. Совместимость APK с 0.11.3 проверена; установка поверх, без удаления данных. Для полного начала новой пары старый разрешённый ключ нужно очистить вручную при остановленном сервере, как описано в инструкции. На физическом Android в этой среде сборка не проверялась, поэтому публикация предварительная.

Результаты: JVM {'tests': 69, 'failures': 0, 'errors': 0, 'skipped': 0}; Python — 7 тестов правил подписи/обновления. Аудиты проекта/архитектуры: 0 ошибок. Lint: {'Error': 0, 'Warning': 17}. APK для Android instrumentation собран, на устройстве не запускался.

Новые проверки: запуск SFTP с явным закрытым доступом; отказы ключевого и парольного входа до локального подтверждения; реальная передача файла после подтверждения; запрет замены ключа на работающем сервере; возврат к закрытому доступу при новом явном запуске в ожидании. Ранее существующий start() с null-ключом всё ещё отклоняется — ожидание включается отдельным startWaiting(). Публичный authenticator проверяет атомарно опубликованный разрешённый ключ, а не наличие открытого порта.

В интерфейсных тестах IP имитируемого Wi-Fi отображается и копируется до существования второго телефона/работающей службы; пустой ключ разрешает запрос закрытого запуска, а повреждённый непустой ключ остаётся ошибкой; выбор файла первого ключа требует явного подтверждения владельца; инструкция загружается из assets без сети. Встроенный текст инструкции сверён побайтно с публикуемым файлом. Сервис не экспортирован другим приложениям; удалённого сетевого API для выдачи разрешений нет.

Адреса читаются локально через ConnectivityManager для Wi-Fi без VPN; при необходимости — через Wi-Fi/AP-интерфейсы устройства. Если Wi-Fi адрес не найден, приложение просит подключиться к Wi-Fi, а не подставляет исторический IP. Поддержка конкретной прошивки/точки доступа требует проверки на устройстве.

Постоянная личность SSH-сервера и encrypted-хранилище закрытых ключей сохранены. При обновлении старое явное разрешение не удаляется автоматически; режим ожидания относится к пустому разрешённому ключу. Ключ клиента разрешается только через локальное подтверждение; если сохранение разрешения не удалось, служба останавливается. Ограничения Android для foreground/dataSync и отдельная папка SFTP остаются прежними.
