# LocalLS Android 0.11.8 — отмена и повтор фоновых передач

LocalLS Android 0.11.8 — отмена и повтор фоновых передач.

Исправлены три ошибки 0.11.7: успешное независимое задание стирало возможность повторить последнее неудачное, несколько нажатий повтора создавали лишние задания, а отмена при открытии назначения могла оставлять пустой файл.

- Последнее неудачное задание и его диагностика сохраняются после успешной соседней передачи. Успешный повтор того же задания снимает ошибку.
- Повторные нажатия не ставят одно задание в очередь несколько раз; недавно завершённое задание с тем же ID не выполняется снова.
- Отмена проверяется до завершения копии, включая пустые файлы и закрытие потоков. Обработанная отмена удаляет созданную текущим заданием копию; исходники и уже завершённые файлы остаются.
- Пустая очередь сразу показывает конечное состояние. Ошибка телеметрии не превращает готовую копию в неудачное задание.

Установи APK поверх 0.11.7 на оба телефона, данные не очищай. После обновления запусти сервер вручную. Ключи доступа и разрешения выбранных папок сохраняются.

[Инструкция: настройка и передача файлов](https://github.com/grigorywork/LocalLS/blob/android-v0.11.8/android/app/src/main/assets/phone-setup.txt). Она также встроена в APK.

101 JVM-тест и 7 Python-тестов прошли без ошибок, lint без ошибок. Прежняя release-подпись, versionCode 28; совместимость обновления с 0.11.7 проверена по пакету, коду и сертификату. Подключённого телефона по ADB нет: аппаратные тесты и установка на физическое устройство не выполнялись.


Проверки: JVM {'tests': 101, 'failures': 0, 'errors': 0, 'skipped': 0}, Lint {'Error': 0, 'Warning': 26}; 7 Python-тестов правил подписи/обновления. Аудиты проекта и архитектуры: 0 ошибок, 84 production-класса, 5 модулей. Сборки release и instrumentation APK прошли. ADB devices пуст; instrumentation не запускался.

Воспроизведение: три новых теста на production-коде 0.11.7 завершились ошибкой. После исправления они проходят. Проверены отмена при открытии назначения для пустого файла, сохранность возможности повтора после успешного независимого задания и многократный повтор одного задания как во время выполнения, так и после завершения. Отдельный тест с намеренно задержанной записью истории воспроизвёл гонку раннего повтора и прошёл после атомарного освобождения задания. Ещё два теста проверяют отмену при закрытии файлового дескриптора и отмену пустой очереди. Тесты используют Robolectric DocumentsProvider и настоящие файловые дескрипторы, управляемые защёлками; исходные байты и отсутствие отменённой копии проверяются отдельно.

Изменения:
- request_id назначается при создании нового задания и сохраняется при повторе. Под общим lock проверяются выполняющиеся и недавно завершённые задания. Последние 256 успешных ID хранятся в памяти процесса; это ограниченная защита от повторного нажатия, не долговременный сетевой протокол идемпотентности.
- Последняя ошибка хранится вместе с Intent задания и безопасной диагностикой. Успешный другой ID её не стирает; успешный тот же ID очищает. Повтор относится к последнему неудачному заданию, а не к неограниченному журналу ошибок.
- Дополнительные проверки поколения отмены выполняются до чтения, после чтения, после закрытия потоков и перед публикацией документа / перемещением временного файла. Собственные временные записи очищаются обработчиком ошибки. Операцию, уже атомарно завершившуюся после последней проверки, нельзя откатить задним числом.
- Отмена без ожидающих заданий сразу показывает «Очередь пуста». Старый прогресс отменённого поколения не обновляет статус. Успех, ошибка и отмена отражаются разными состояниями телеметрии; исключение записи истории не меняет результат уже завершённой копии.

Сохранены авторизация только по ключу, pinning fingerprint, выбранные SAF-папки, автосохранение с SQLite-журналом из 0.11.7 и постоянный сертификат. Новых разрешений или передачи ключей не добавлено.

Ограничения: сетевая очередь, последняя ошибка и список успешных ID остаются process-local; после принудительной остановки задания не восстанавливаются. Повтор папки выполняет задание заново, а не продолжает его с точного файла, поэтому уже завершённые части могут получить дополнительные копии. Отмена может ждать возврата провайдера/сетевого вызова; закрытый поток и созданный документ очищаются после возврата. Поддержка OEM-фона требует проверки на телефоне.
