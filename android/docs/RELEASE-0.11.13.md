# LocalLS Android 0.11.13 — восстановление привязки доступа

LocalLS Android 0.11.13 — восстановление сохранённого доступа после смены IP в старой версии.

«Проверить SSH» теперь может восстановить потерянную привязку ключа к адресу. Это помогает, если IP уже поменяли через старый экран «Сеть», а ключ остался у прежнего адреса.

Восстановление выполняется только при точном совпадении текущего fingerprint с ранее доверенным сервером, прежнем порте и пользователе, отсутствии сохранённого ключа нового адреса и одной уникальной найденной клиентской паре. Новый сервер, конфликтующий fingerprint, несколько разных пар или существующий/нечитаемый ключ назначения не заменяются автоматически. Новых ключей, паролей и кнопок нет.

После обновления включи сервер на телефоне 1. На телефоне 2 проверь его IP в существующем подключении и нажми «Проверить SSH». При выполнении условий доступ восстановится без повторного создания ключа и передачи .pub. Не сбрасывай ключи и fingerprint.

Постоянная release-подпись прежняя, versionCode 33 > 32. Устанавливай поверх 0.11.12 на оба телефона без удаления и очистки данных. Компактная строка IP без кнопки копирования, передача папок, фоновые службы и исправление экрана «Сеть» сохранены.

[Инструкция](https://github.com/grigorywork/LocalLS/blob/android-v0.11.13/android/app/src/main/assets/phone-setup.txt) обновлена и встроена в APK.

129 JVM-тестов и 7 Python-тестов прошли без ошибок и пропусков, lint без ошибок. Проверены восстановление с настоящим SSH/SFTP-сервером на другом loopback IP и отказы в семи небезопасных/неподходящих случаях. В полном наборе также прошли передача 60 МиБ в обе стороны, смена IP и независимый OpenSSH-клиент.

На физических телефонах установка и Wi-Fi не проверялись. В тестах маршрутов Android Keystore заменён памятью. Изоляцию клиентов на роутере обновление не снимает; у телефонов должны быть разные IP, но разрешённый сетевой доступ друг к другу. При неоднозначном выборе ключей требуется прежнее подключение с нужной парой; отдельного списка выбора пары в этой ревизии нет.


Проверки: JVM {'tests': 129, 'failures': 0, 'errors': 0, 'skipped': 0}, Lint {'Error': 0, 'Warning': 26}; Python 7 тестов обновления/подписи. Аудиты без ошибок, 85 production-классов / 5 модулей. Release и instrumentation APK собраны. ADB devices пуст; физическая установка, Android Keystore, радио/роутер Wi-Fi и OEM-фон не проверены.

Проблема: 0.11.12 исправляла будущие сохранения адреса через «Сеть», но не восстанавливала связь, уже потерянную при прежнем изменении IP. Ключ и доверенный fingerprint оставались у старого адреса, текущий профиль содержал новый. Два теста AccessRecoveryTest на production-0.11.12 сначала упали: новый IP без pin и новый IP с уже подтверждённым pin, но отсутствующим ключом (reproduce.log). После исправления целевой прогон прошёл (recovery-tests.log), затем полный прогон с ещё тремя защитными сценариями (verified-build.log).

Алгоритм: контекстный SshClient.probe сначала выполняет обычную проверку без доступного ключа. Она получает host fingerprint без клиентской авторизации. Только если ключ отсутствует и нет несовпадения fingerprint, SshKeys.recoverRoute ищет в локальном HostTrustStore прежние адреса с точно тем же fingerprint и портом. Для текущего пользователя проверяются сохранённые пары. Несколько адресов с одной парой допустимы; несколько разных пар не выбираются автоматически. Любая запись ключа назначения, включая нечитаемую, запрещает восстановление. Иной существующий pin назначения тоже запрещает его. При однозначном совпадении вызывается обычный moveRoute, исходные данные не удаляются. Потом probe повторяет обмен и строгую проверку pin перед авторизацией, поэтому доверие не основано только на ранее полученном снимке сети.

HostTrustStore.hostsForFingerprint читает только локальные записи прежнего доверия; не сканирует сеть, не делает DNS/HTTP-запросы и не создаёт новое доверие по IP или имени Wi-Fi. Приватные ключи не генерируются и не экспортируются. Существующий AES-GCM / Android Keystore используется без изменения. Активный профиль не меняется. Ошибка сохранения не запускает авторизацию с непроверенным ключом; пользователю сообщается о неудачном восстановлении без текста секретного исключения. Это не обходит необходимость первоначального разрешения .pub и сверки host fingerprint на новом сервере.

Девять новых живых SSH-сценариев используют разные loopback IP и настоящий EmbeddedSftpServer: восстановление у нового IP без pin с последующим SFTP-чтением; восстановление у уже подтверждённого IP без ключа; отказ при незнакомой личности сервера; отказ при нескольких разных парах; отказ перезаписать существующий ключ назначения; отказ при конфликтующем pin; отказ использовать ключ другого пользователя; отказ использовать доверие/ключ другого порта; отказ перезаписать нечитаемую сохранённую запись. SecurePrefs в этих JVM-тестах заменён памятью, не имитирует надёжность реального Android Keystore. Старые проверки подмены SSH-сервера до авторизации, разных IP, 60 МиБ и конфликтов маршрутов также прошли в общем наборе.

Ограничения: восстановление выполняется полной проверкой SSH в клиентском приложении, а не произвольной SFTP-операцией; нужен работающий сервер и уже доверенная host key. Если сервер сменил личность, клиентская пара удалена/повреждена, Keystore недоступен, есть несколько подходящих пар или ключ нового адреса уже существует, автоматическая замена не выполняется. Отдельного выбора пары нет. Это восстановление привязки существующей пары, не восстановление уничтоженного приватного ключа. При недоступности сети сначала требуется исправить адрес/маршрут/настройки роутера. Прежние ограничения очереди, повтора папок и фоновой работы сохраняются.
