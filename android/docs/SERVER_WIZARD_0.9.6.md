# Android 0.9.6: единый мастер сервера

Основа: main 45482d1 (единый опубликованный 0.9.5), PR #1 уже объединён.
Задачи: #2 и #3; передачи (#4), Windows (#5) и Fedora (#6) — следующие этапы.
Windows и Fedora остаются 0.9.5. Актуальные версии описывает versions.json.

В боковом меню «Этот телефон — сервер» открывает существующий ServerSetupActivity.
Шесть статусов показывают Termux, первый запуск/SAF, RUN_COMMAND, SSH-вход,
SSH-ключ и HTTPS-агент. Полная готовность требует фактической проверки всех шагов.
Проверенный SSH можно экспортировать отдельно, если настройка ключа/агента отложена;
публичный localls-server-v1 не содержит пароля, token или приватного ключа.

Первоначальная установка/открытие Termux и системные разрешения требуют пользователя.
После подготовки ключа и согласия на агент обычная кнопка подготовки повторно
проверяет SSH и ключ, сохраняет работающий sshd и проверяет существующий HTTPS-агент.
SSH-пароль автоматически не выключается. Выбранный удалённый профиль, его секреты
и режим HTTP/HTTPS мастером не переписываются.

Используются прежние Termux SAF/RUN_COMMAND, SshKeys, SftpClient и AgentTls/AgentClient.
Отпечаток SSH сравнивается с публичными host keys, полученными от Termux, до отправки
пароля. Создаётся только недостающий ключ локального профиля, authorized_keys
сохраняется; проверка нового ключа выполняется отдельным соединением publickey-only.

Python/OpenSSL устанавливаются только при отсутствии. Обновление агента не создаёт
второй SSH/boot-механизм. Активный HTTPS-агент повторно используется без замены процесса,
конфигурации, token или сертификатов. Старый HTTP-агент требует отдельной миграции;
занятый порт, symlink, слабые права, неполная TLS-пара и неподтверждённый ответ дают
отказ с понятной причиной. Приватный TLS-ключ приложение не читает, token получает
через разрешённый SAF и передаёт только по проверенному HTTPS, без логов/экспорта.

Открытие терминала не выполняет ручных команд за пользователя. Файлы свойств
проверяются до/после изменения; при сбое записи выполняется попытка возврата
исходного содержимого. Скрипты staging имеют уникальное имя и удаляют только свои
два файла. Идентификаторы callback — одноразовые, сырой stdout/stderr не сохраняется.

Подписи Termux сверяются с upstream TermuxConstants.java:
https://github.com/termux/termux-app/blob/master/termux-shared/src/main/java/com/termux/shared/termux/TermuxConstants.java
Протокол: https://github.com/termux/termux-app/wiki/RUN_COMMAND-Intent
Известная подпись GitHub Termux использует опубликованный debug-ключ; сама по себе
она не доказывает происхождение APK. Termux нужно устанавливать из официального
источника. Проверяется также принадлежность SAF-поставщика com.termux.documents.

## Реальные проверки

Финальные результаты указываются в BUILD_REPORT.md после выполнения gates.
Preview подписан ключом среды сборки; совместимый итог требует прежнего сертификата
3b4c5a568105f73bf999f288a041255a57ee5cfc83253b99e5f2c07789f1f9ba.
0.9.5 и старые теги/установщики сохраняются.

Физические телефоны не подключены. Первоначальные Android-разрешения, настоящий
Termux/OpenSSH на телефоне, его нестандартные параметры запуска/ListenAddress,
перезапуск устройства и ограничения батареи требуют отдельного device smoke test.
Тесты установщика агента выполняются на изолированных временных папках/портах;
работающий sshd машины сборки не меняется.
