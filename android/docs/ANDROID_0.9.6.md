# Android 0.9.6 — SSH-ключи и проверка обновлений

Работа ведётся только над Android. Windows и Fedora остаются 0.9.5. Метаданные
Android вынесены в release.properties: versionName 0.9.6, versionCode 15.

## Вход

Обычный SSH/SFTP-клиент всегда выбирает ключ. Удалены поле пароля, переключатель
его сохранения и возможность выключить ключевой режим. ConfigMigrator удаляет
старый пароль и его шифротекст, сохраняя ключи, адреса, fingerprint и токен агента.
Отсутствующий/неверный ключ приводит к отказу, а не к попытке парольного входа.
Удалены неиспользуемый SessionPassword и методы сохранения/чтения SSH-пароля.

В «Подключение» добавлена кнопка «Настроить вход по SSH-ключу». Можно создать RSA
3072 либо импортировать поддерживаемый ключ. Приватный ключ хранится зашифрованным
с помощью Android Keystore, экспортируется только публичная часть.

Для первичной установки публичного ключа сохранён отдельный шаг с действующим
паролем сервера: добавить ключ, проверить отдельный вход publickey, удалить пароль.
Одноразовый пароль не сохраняется. Мастер этого телефона также сохраняет подготовку
сервера через пароль до установки ключа. Это не обычный режим подключения клиента.
Настройки sshd и парольный вход на самом сервере автоматически не отключаются:
другие клиенты должны сначала получить и проверить собственные ключи.

## Подпись и обновления

Release-проверка требует приватный ключ с сертификатом опубликованной 0.9.5:
`3b4c5a568105f73bf999f288a041255a57ee5cfc83253b99e5f2c07789f1f9ba`.
Попытка использовать другой keystore реально испытана: Gradle блокирует сборку
сообщением о несовместимом сертификате.

Верификатор APK проверяет криптографическую подпись, структуру, выравнивание и
метаданные. С `--previous-apk` дополнительно требует тот же applicationId,
один и тот же сертификат и строго больший versionCode. Для
`--require-release-signer` предыдущий APK обязателен. Команда полного релизного
процесса: `bash tools/build_release.sh /absolute/path/previous-official.apk`.
Секреты задаются только через LOCALLS_RELEASE_* в защищённой среде.

Локальная сборка подписана сохранённым ключом этой среды:
`271e250e10335ecf0a19af826fbd6cc465b6bb0a2002e095be6fcfcad9bff9d1`.
Совместимость с LocalLS-audit-2026-10-15.apk проверена по двум настоящим APK:
сертификаты совпадают, applicationId совпадает, code 14 → 15. Это проверка условий
обновления, а не фактическая установка на физическом телефоне.

Скачанный официальный LocalLS-v0.9.5-debug.apk имеет другую подпись; проверка
обновления отклоняет его. Приватного ключа официального APK в этой среде по-прежнему
нет. Поэтому 0.9.6 здесь нельзя выдавать за совместимый официальный выпуск.
Смена сертификата в release.properties не восстанавливает утраченный ключ.

## Проверки

- Миграция сохраняет SSH-ключи/токен/адрес и удаляет пароль; повторный запуск безопасен.
- Настоящий SSH fixture считает парольные аутентификации: обычный клиент при
  отсутствии ключа не отправляет даже переданный ему действующий пароль.
- Существующий тест проверяет, что отклонённый ключ не включает password fallback.
- Четыре Python-теста правил обновления: успех, другой сертификат, другой package,
  прежний/меньший versionCode.
- В Android CI добавлены проверки метаданных и правил обновления. На GitHub новый
  workflow в этой сессии не запускался; изменения и артефакты пока локальные.
- Instrumentation APK собирается, но запуск на физическом Android не выполнен.
