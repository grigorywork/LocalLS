# Аудит LocalLS Android 0.11.16

Дата: 21 октября 2026. Проверяемая исходная версия: 0.11.15; исправления включены в 0.11.16. Объём: Android APK, файловые операции, SSH/SFTP, хранение доступа, фоновые операции и обновление. Windows/Fedora не менялись. Это разбор кода и автоматические проверки на стенде; физические телефоны к среде не подключены.

| Приоритет | Найденная ошибка | Исправление и проверка |
| --- | --- | --- |
| P1 — потеря файлов | JSch раскрывал `*` и `?` в пути как шаблон. Удаление буквального `*.txt` затрагивало соседний `keep.txt`; аналогично удалялись несколько пустых каталогов. | Экранирование на границе JSch, без изменения настоящих имён в интерфейсе. Проверены удаление одного файла/каталога и сохранность соседей; просмотр, копирование, скачивание и переименование в каталоге с `*`. `mkdir` оставлен буквальным: эта операция JSch шаблоны не раскрывает. |
| P1 — перезапись при загрузке | Имя выбиралось до длительной записи. Если другой файл занимал его во время передачи, POSIX rename заменял этот файл. | Имя выбирается после загрузки временного файла. Встроенный сервер не объявляет POSIX rename/создание ссылок и отвергает переименование с заменой/atomic-флагами; обычное перемещение не запрашивает замену. При занятом имени клиент пробует другое, максимум 16 попыток. Проверены коллизия во время записи и создание файла непосредственно в серверном обработчике перед окончательным перемещением. Оба набора байтов сохраняются раздельно. |
| P2 — потеря привязки доступа | Ручная смена IP отличала только пустые расшифрованные данные. Уже существующая, но нечитаемая запись назначения могла получить чужую привязку. | `moveRoute` проверяет отдельно присутствие записи. При нечитаемом существующем ключе возвращает отказ до записи ключей, алиасов и доверенного fingerprint. Тест проверяет неизменность записей и параметров. Пустое место для нового маршрута по-прежнему допускается. |
| P2 — неверное завершение отменённой копии | Общий локальный экспорт проверял прерывание только внутри цикла чтения. Отмена на последнем блоке, при закрытии провайдера и уже прерванная пустая копия могли завершиться публикацией. | Прерывание проверяется до открытия и перед публикацией; callback владельца повторно проверяется после закрытия потоков. Три граничных теста и сценарий AutoReceive с заблокированным закрытием провайдера: новая копия удалена, исходник сохранён, запись остаётся ожидающей, новый запуск успешно повторяет сохранение. |

Все четыре группы воспроизведены на исходном коде 0.11.15 до исправления: 4 неуспешных SFTP-сценария, 1 сценарий ключа, 3 сценария отмены. Ещё два теста проверяют окончательную коллизию на сервере и повтор AutoReceive после остановки. Результаты полного прогона, Lint, подписи и хеш APK приведены в [отчёте выпуска](RELEASE-0.11.16.md).

Проверены существующие защитные границы:

- Строгая проверка SSH fingerprint до клиентской авторизации; неизвестный ключ, пароль и неверный пользователь встроенным сервером не принимаются. Команды, shell, forwarding и создание файловых ссылок запрещены. Проверки обхода серверной папки и перезапуска сервера входят в общий прогон.
- Сервер предоставляет приватную папку LocalLS. Доступ к папкам телефона осуществляется через системные URI-разрешения или собственные записи Downloads; широких прав на всю память не добавлено.
- По разбору исходников закрытые SSH-ключи шифруются AES-GCM с ключом Android Keystore, APK не содержит ключ подписи. Host key не пересоздаётся автоматически при наличии нечитаемой записи. Работа реального Android Keystore на конкретном телефоне этим стендом не проверена.
- Службы, настройки и файловые экраны не экспортированы. Входной MainActivity принимает ссылки content URI с ограничением количества. Автоматический cloud backup и device transfer данных приложения запрещены манифестом/правилами.
- Штатный HTTPS-агент требует pin сертификата до передачи токена и не следует перенаправлениям. Старый HTTP-режим остаётся явной настройкой совместимости; его трафик не шифруется. Он не используется встроенным телефонным SFTP-сервером. Этот аудит его не удалял.
- Очередь передачи сохраняет адрес, пользователя и fingerprint задания. Прежние тесты смены профиля/роли, утраты старой привязки, отмены/повтора, 60 МиБ и независимых папок включены в полный прогон.

Границы результата:

1. Обновить нужно оба телефона. Защита от перезаписывающего rename действует у встроенного сервера 0.11.16. У стороннего/старого сервера, который использует POSIX rename с заменой, клиентский повторный выбор имени уменьшает окно коллизии, но не гарантирует отказ от замены между проверкой и операцией. Это свойство удалённого протокола/реализации; стенд не доказывает транзакционность всех файловых провайдеров и произвольных внешних писателей.
2. Встроенный сервер остаётся файловым сервером с записью для разрешённого ключа. Запрет перезаписывающего rename не превращает его в хранилище только для добавления: авторизованный клиент может явно открыть существующий файл для записи или удалить его. Политика доверия ключу не менялась.
3. Сетевая очередь остаётся process-local; после уничтожения процесса требуется повтор. Повтор папки может повторно скопировать уже завершённые элементы. SQLite-очередь автосохранения сохраняется. Для пустых папок нужен провайдер SAF; виртуальное представление Downloads определяется записями MediaStore.
4. Провайдер Android может блокировать I/O или отказать в разрешении. Ограничения батареи/OEM, реальные Wi-Fi, установка APK и особенности каждого Android не проверены на физическом устройстве. Собранный instrumentation APK сам по себе не означает запуск этих тестов.
5. Lint-предупреждения перечислены в отчёте выпуска. Аудит не является заключением об отсутствии всех уязвимостей и не включает независимую проверку всех CVE зависимостей.
