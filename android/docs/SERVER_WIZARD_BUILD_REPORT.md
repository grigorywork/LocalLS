# Проверка Android-мастера: подготовка сервера и HTTPS-агента

Основа: GitHub `grigorywork/LocalLS`, `main` / `45482d1` (0.9.5).
Рабочая ветка: `codex/android-server-wizard-readiness`. Это продолжение GitHub #2/#3,
а не опубликованный выпуск 0.9.6. Версии остальных клиентов сохраняются.

## Изменения

Мастер проверяет семь шагов: Termux, реальный SAF-доступ, RUN_COMMAND,
подготовку OpenSSH, парольный вход SSH, отдельный ключевой вход и HTTPS-статус агента.
Проверки безопасности и экспорт связаны с текущей подготовкой/пользователем/портом;
смена состояния или потеря доступа сбрасывает подтверждение.

Новая кнопка «Подготовить HTTPS-агент» работает через уже проверенное локальное
SSH-соединение с host-key pinning. Если ключевой вход проверен, используется только
этот ключ; иначе нужен действующий пароль. Учётные данные не входят в shell-команду.
Код агента и установщика включён в APK как assets из исходников realme-agent;
при сборке используется Android Variant API для generated assets.

Установка добавляет Python/OpenSSL/procps при необходимости, создаёт новые token/TLS
только при их отсутствии и запускает независимый агент. Существующие config.json,
token, полноценная TLS-пара, SSH-конфигурация, host keys, sshd и boot-схема сохраняются.
Рабочий проверенный агент не перезапускается; остановленный можно обновить атомарно.
Мастер не добавляет автозапуск. Конфигурация и TLS-ключ сохраняются в приватном
Termux HOME с правами 600; клиентские SSH-ключи — зашифрованными в Keystore.

Подготовки сериализуются через flock. Занятый порт, старый HTTP-режим, неполная/
повреждённая/истёкшая TLS-пара и небезопасные ссылки вызывают безопасный отказ.
Сырой вывод и секреты не появляются в интерфейсе. Токен передаётся только после
TLS-проверки и сравнения точного сертификата; pin снова проверяется на соединении
с авторизацией. После подготовки Android отдельно выполняет HTTPS /status через SAF
сертификат и показывает успех только при подтверждённом результате.

## Выполненные проверки

`BUILD SUCCESSFUL`, итоговая сборка 1 минута 10 секунд.
JDK Temurin 17.0.20.1+1, Gradle 9.6.0, AGP 9.4.1, SDK 37, Build Tools 36.0.0.

```text
:core:test :transport:testDebugUnitTest :app:testDebugUnitTest
:app:assembleDebug :app:assembleDebugAndroidTest :app:lintDebug
```

Всего 33 теста пройдены, без ошибок и пропусков:

- 21 JVM/Robolectric, в том числе четыре реальных SSH/SFTP/HTTPS fixture-теста.
- 8 новых Python-тестов установщика: новый запуск; повтор без второго процесса;
  обновление остановленного агента с сохранением секретов; неполная TLS-пара;
  занятый порт; legacy HTTP; параллельная подготовка; symlink; публичный CLI-marker.
  Несколько сценариев объединены в один тест.
- 4 Python HTTPS-теста существующего агента.

Проверка состояния Android использует Robolectric; сетевые fixtures — изолированные
loopback AsyncSSH 2.21.1 и настоящий Python HTTPS-агент. Отрисовка проверена на
360 × 640 dp со шрифтом 100/150/200%; создан 21 снимок проверяемых экранов.
Проектный/архитектурный аудит — 0 ошибок. Lint — 0 ошибок,
15 прежних предупреждений. Контроль версий пройден.
Тесты установщика добавлены в Android CI; YAML приведён к LF.

В Java сохранены штатный proxy и проверка TLS через системные CA; только локальные
fixtures включены в http.nonProxyHosts. Настройка среды находится вне репозитория.
Для четырёх JVM integration-тестов используется LOCALLS_SECURITY_FIXTURE, который
задаёт новую приватную папку tools/security_fixture.py. Без него эти четыре теста
явно пропускаются; в данном прогоне все выполнены. Секреты генерируются при запуске.
Python-проверки: tools/test_agent_setup.py и tools/test_agent_security.py.

## Оставшиеся проверки и публикация

Физический Android и Android-эмулятор не подключены. Установка пакетов в реальном
Termux, полный SAF → SSH → shell bootstrap → HTTPS путь на телефоне, сворачивание,
системные ограничения батареи и instrumentation-тесты ещё не проверены.
Python установщик и HTTPS-процесс испытаны реально; это не заменяет Android runtime.

Legacy HTTP и рабочий агент другой версии автоматически не мигрируются: мастер
сохраняет их и просит отдельную проверку. Собственный механизм boot не создаётся.
Для релиза нужны отдельная Android-версия 0.9.6, новый versionCode, совместимый
сертификат владельца и проверка на устройстве. Задача #2 остаётся открытой.
Публикация/PR на GitHub не выполнены: настроенный GH_TOKEN не проходит авторизацию.
Сохранены APK, тестовый APK, исходники, переносимый патч и журнал сборки.
