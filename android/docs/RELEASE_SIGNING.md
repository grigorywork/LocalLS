# Постоянная подпись LocalLS Android

Начиная с 0.9.9 (versionCode 18), по решению владельца начинается новая цепочка подписи.
Совместимость со старыми официальными и локальными debug APK не сохраняется.
Идентификатор приложения остаётся com.bitpoint.homeservercontrol. Старую установленную
версию новый сертификат не обновит. Удаление приложения удаляет локальные данные и SSH-ключи;
перед переходом необходимо сохранить доступ к серверу. Приложение автоматически не удаляется.

Публичный SHA-256 сертификата закреплён в android/release.properties.
Закрытый ключ создан один раз, RSA 3072, PKCS12, срок сертификата 10000 дней.
Он не включён в исходники, APK, GitHub или публичный архив.
В текущей среде защищённый каталог: /workspace/private/localls-signing (0700),
keystore и файл пароля имеют права 0600. Владелец должен сохранить защищённую резервную
копию каталога вне временной рабочей среды. Потеря ключа снова нарушит совместимость обновлений.

Переменные защищённой среды сборки:
- LOCALLS_RELEASE_STORE: путь к существующему keystore;
- LOCALLS_RELEASE_STORE_PASSWORD: пароль keystore;
- LOCALLS_RELEASE_KEY_ALIAS: localls-release;
- LOCALLS_RELEASE_KEY_PASSWORD: пароль ключа;
- ANDROID_HOME: Android SDK.

Для первой сборки: tools/build_release.sh --initial-release.
Этот режим допускается только при коде версии, равном releaseBaselineVersionCode=18,
и при совпадении подписи с закреплённым release-сертификатом.
Для следующих: tools/build_release.sh /absolute/path/to/previous-release.apk.
Проверяются неизменный package, тот же сертификат и строго больший versionCode.
Release-сборка имеет debuggable=false. Debug APK остаются только для разработки.

GitHub Actions verification пока собирает debug APK; эти артефакты не являются
официальными обновлениями новой release-цепочки. Для release в CI нужно отдельно
настроить защищённое хранение того же ключа. Новый ключ автоматически не генерируется.
