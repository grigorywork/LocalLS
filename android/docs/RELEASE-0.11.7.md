# LocalLS Android 0.11.7 — восстановление очереди автосохранения

LocalLS Android 0.11.7 — исправление очереди автосохранения.

В 0.11.6 первый файл с ошибкой записи или удалённым исходником мог задерживать остальные. Теперь независимые файлы продолжают сохраняться, а неудачные остаются для повтора.

- Удалённые исходники пропускаются с сообщением; они не блокируют следующие загрузки.
- Ошибка одного файла не задерживает остальные. «Повторить сохранение» обрабатывает только ожидающие файлы.
- Повторно присланный файл под прежним именем сохраняется, даже если прежняя запись была пропущена как удалённая.
- Объединены повторные запросы к фоновому исполнителю; проверен приём пачки файлов во время занятого копирования.
- Существующая очередь 0.11.6 открывается без сброса базы, ключей и настроек.

Установи APK поверх 0.11.6 на оба телефона, данные не очищай. На телефоне-сервере после обновления включи сервер; зависшие ожидающие сохранения будут обработаны. Закрытый ключ и разрешённый публичный ключ пересоздавать не нужно.

[Инструкция: два телефона](https://github.com/grigorywork/LocalLS/blob/android-v0.11.7/android/app/src/main/assets/phone-setup.txt). Инструкция также встроена в APK.

Оба теста проходят после исправления. Добавлены ещё проверки повторного получения удалённого пути с теми же метаданными, пачки из 16 файлов при заблокированной первой записи и открытия реальной таблицы формата 0.11.6 без сброса.

AutoReceive проходит ожидающие строки по rowid, пробуя каждый элемент один раз за проход. Сбой записи оставляет строку pending, однако обход продолжается со следующего id. Отсутствующий исходник отмечается пропущенным (saved=2); сообщение содержит число пропусков. Состояние 2 позволяет принять заново тот же путь/размер/mtime. Отметка завершения защищена id строки и метаданными: завершение старой копии не закрывает новое задание для того же пути. Схема базы остаётся version=1 и совместима с таблицей 0.11.6.

AtomicBoolean объединяет запросы к одному исполнителю, сохраняя запрос, пришедший во время работы. Исключение чтения/записи базы отражается в диагностике; неуспешный SQLite insert больше не игнорируется. Статус завершения записывается до active=false, чтобы интерфейс видел итог прохода.

Параметры SSH/SFTP, авторизация только по ключу, проверка fingerprint, роли устройств, доступ к SAF/MediaStore и постоянный сертификат сохранены. Приватный материал подписи не публикуется. При обработанной ошибке исходные файлы остаются в LocalLS. По-прежнему нет восстановления сетевой очереди после убийства процесса; журнал автосохранения имеет семантику at-least-once и авария после публикации копии может создать дополнительную копию. Никакая автоматическая синхронизация или удаление пользовательских исходников не добавлялись.
