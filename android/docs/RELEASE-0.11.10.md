# LocalLS Android 0.11.10 — IP Wi-Fi и безопасность смены адреса

LocalLS Android 0.11.10 — текущий IP Wi-Fi и сохранность ключей при смене адреса.

- В блоке «Мой сервер» на главном экране и в настройке своего сервера появился «Текущий IP Wi-Fi». Зелёным показан адрес этого телефона, отдельно от состояния сервера. Без Wi-Fi выводится подсказка, старый адрес не сохраняется на экране.
- «Скопировать IP» копирует только адрес. При смене адреса перед копированием показывается новый и требуется повторное нажатие. При нескольких адресах можно выбрать; выбранный адрес проверяется ещё раз перед копированием.
- Адрес обновляется, пока экран открыт, и при возвращении. VPN и мобильная сеть не подставляются в Wi-Fi IP; точка доступа поддерживается резервным поиском её интерфейса, с учётом ограничений производителя.
- Исправлена коллизия хранения ключей: разные клиентские ключи одного сервера и пользователя больше не перезаписывают друг друга при переносе IP. Существующие маршруты читаются без сброса, старые алиасы не удаляются.
- Проверено блокирование другого SSH-сервера по несовпадающему fingerprint до авторизации. Не нужны новые ключи или пароли при обычной смене Wi-Fi того же сервера.

Как пользоваться: оба телефона подключены к одной доступной сети. На телефоне 1 включи сервер и посмотри «Мой сервер → Текущий IP Wi-Fi». На телефоне 2 в существующем подключении замени только IP, сохрани и нажми «Проверить SSH». Порт и пользователь прежние. Из разных Wi-Fi нужен общий защищённый маршрут/VPN: локальный IP сам по себе не обеспечивает интернет-доступ.

Установи APK поверх 0.11.9 на оба телефона без удаления и очистки данных, затем включи сервер вручную. Постоянный release-сертификат прежний, versionCode 30 > 29.

[Инструкция с нуля и смена Wi-Fi](https://github.com/grigorywork/LocalLS/blob/android-v0.11.10/android/app/src/main/assets/phone-setup.txt) встроена в APK. IP определяется локально; новая функция не меняет сохранённое подключение, доверие серверу и разрешения, не запускает сервер и не отправляет адрес внешним сайтам.

117 JVM-тестов и 7 Python-тестов прошли, lint без ошибок. Совместимость обновления с 0.11.9 проверена по пакету, сертификату и коду версии. Физический телефон не подключён: установка, реальные Wi-Fi/точки доступа и работа на конкретном производителе здесь не проверялись.

Отображаются IPv4-адреса. Сервер по-прежнему слушает сетевые интерфейсы телефона; строка Wi-Fi IP не является межсетевым экраном. Не подтверждай неожиданную замену fingerprint без сверки на телефоне-сервере. Ограничения повторов, фоновой работы и копирования из предыдущих ревизий сохраняются.

Состав изменений: новый WifiAddressView повторно используется главным экраном и EmbeddedServerActivity. Он использует существующий LocalServerAddresses: ConnectivityManager / LinkProperties и ограниченный резервный поиск активных WLAN/AP-интерфейсов. Новых разрешений, локального сканирования, внешних HTTP-запросов, фоновых потоков или фонового слежения за сетью для этой функции нет. IPv4 фильтрует loopback, unspecified, link-local и multicast; сети с transport VPN/Cellular не используются как Wi-Fi. Список сортируется, чтобы порядок не менял показания. При нескольких Wi-Fi адресах выбирает пользователь. Обновление выполняется существующим экранным таймером раз в секунду и при onResume, прекращается при onPause.

Буфер обмена: только выбранный IP. Перед началом копирования список перечитывается; изменение списка требует нового нажатия. После выбора из диалога адрес ещё раз проверяется. Отсутствующий IP не копируется; старый буфер не стирается. Это проверка снимка на момент нажатия, а не блокировка DHCP — сеть может измениться и сразу после копирования. Обновлённое поле расположено в собственном серверном блоке и не меняет поля удалённого подключения. В настройке сервера IP больше не повторяется в соседней строке параметров; полное копирование данных подключения оставлено отдельной операцией.

Безопасность маршрутов: старый слот логического ключа зависел только от fingerprint сервера и пользователя. Два исходных профиля с разными клиентскими парами, но одинаковой личностью сервера, при независимом переносе на новые IP записывали один слот; первый профиль получал второй ключ. Это воспроизведено RouteIdentityTest.addressChangesNeverReplaceAnotherIdentityOfSameServerUser на production-реализации 0.11.9 (identity-reproduce.log). Новый слот учитывает fingerprint клиентского ключа дополнительно к серверу и пользователю. Читаются старые алиасы, при переносе создаётся новый и обновляются только два перемещаемых маршрута. Старые слоты не удаляются. Конфликтующий pin или уже существующая иная клиентская пара назначения не перезаписываются. Проверены независимость двух пар, несколько последовательных смен Wi-Fi, отказ при конфликте и чтение старого алиаса. Хранилище SecurePrefs в этих JVM-тестах заменено памятью; фактическая Android Keystore-персистентность на устройстве не проверялась.

Проверка личности сервера: отдельный живой loopback SSH-сервер с другой host key и счётчиком авторизаций отвергается клиентом SftpClient.TreeSession. Счётчик остаётся 0 — ключ клиента не предлагается до проверки pin. Существующие тесты также проверяют запрет парольного входа, shell/exec, forwarding, ссылок/выхода из общей папки и доступ до локального разрешения клиента. Это функциональная проверка конкретных механизмов, а не полный независимый аудит безопасности приложения, Android или сети.

Закрытые SSH-ключи остаются в приватном хранилище приложения, зашифрованном AES-GCM ключом Android Keystore; clipboard нового пункта их не читает. Сервер работает с разрешённым публичным ключом и прежним приватным корнем SFTP. allowBackup=false, manifest и серверная политика в этой ревизии не изменены. Сервер слушает все предусмотренные существующей реализацией сетевые интерфейсы: показ Wi-Fi IP не ограничивает bind. Первое разрешение .pub и проверка host fingerprint по доверенному экрану сервера обязательны; сбрасывание pin или слепое подтверждение подмены может снять защиту. Разные Wi-Fi требуют маршрута/VPN, его настройка в эту ревизию не входит.

Шесть новых UI/сетевых JVM-сценариев: показ собственного IP до запуска сервера и копирование без изменения удалённого профиля; смена адреса и отключение Wi-Fi; изменение адреса до нажатия; исключение VPN/Cellular и непригодных адресов; выбор из нескольких адресов и его повторная проверка; отсутствие Wi-Fi. Добавлены четыре сценария маршрутов и один живой SSH-тест. Существующая проверка сетапа адаптирована к отдельному полю IP; проверки тем и масштаба шрифта 1 / 1.5 / 2 выполняются для обновлённого главного экрана.
