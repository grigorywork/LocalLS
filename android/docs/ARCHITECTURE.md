# Модули LocalLS

Рефакторинг от 8 октября 2026 на основе main 101a888. applicationId, имена экранов,
ключи SharedPreferences, alias Android Keystore и серверный протокол сохранены.

| Модуль | Ответственность | Зависимости |
|---|---|---|
| core | Конфигурационные константы, модели ответов, секреты в памяти, скрытие секретов | JDK 17 |
| data | SharedPreferences, Keystore, история, SAF и данные скорости | core, Android |
| transport | SSH/SFTP, pinning, поиск сервера, HTTP-клиент агента | core, data (Keystore для SSH-ключей), Android JSON, JSch |
| ui | Темы, рисунки/рамки, типографика, графики и раскрывающиеся разделы | core, data, Android |
| app | Экраны, Android services/receivers и связывание функций | все четыре модуля |

UI-ресурсы используют namespace com.bitpoint.homeservercontrol.ui. Экраны и их R.id/R.layout
остаются в app; ссылки на R.attr/R.color/R.drawable/R.style оформлены через UI namespace.
Non-transitive R остаётся включённым.

Java package com.bitpoint.homeservercontrol сохранён при переносе: это поддерживает
существующие package-private API и instrumentation tests. Это ограничение текущего этапа:
модули разделены сборкой и проверкой направления зависимостей, но Java package пока общий.
Очередь файлов с 0.11.6 принадлежит TransferForegroundService; закрытие Activity не отменяет передачу.
Для последующего рефакторинга остаются явные публичные интерфейсы, отдельные Java-пакеты
и выделение контроллеров MainActivity. Исторические отчёты ниже описывают состояние прежних версий.

Проверки:

```text
python tools/audit_project.py
python tools/audit_architecture.py
./gradlew :core:test :transport:testDebugUnitTest :app:testDebugUnitTest :app:assembleDebug :app:assembleDebugAndroidTest :app:lintDebug
./gradlew :app:connectedDebugAndroidTest
```

Последняя команда требует подключённого Android-устройства/эмулятора. Сборка test APK
не означает выполнение instrumentation tests. Сетевые SSH/SFTP fixture tests запускаются
только с явными параметрами отдельного тестового сервера.

ActionGridLayout переносит действия в дополнительные строки при крупном шрифте.
ControlsScrollView оставляет место для списка файлов при увеличении текста.
Результаты двух тестов отрисовки (18 изображений) и полного Gradle build gate
зафиксированы в LOCAL_BUILD_REPORT.md и docs/verification-2026-10-09.json.

## Аудит и рефакторинг 15 октября 2026

- `core/DirectoryRequestState` владеет поколением запросов каталога и разрешением
  записи. Activity применяет только актуальный результат, включая повторный переход
  A → B → A; закрытие экрана инвалидирует ожидающие ответы.
- `transport/SshCommandExecutor` владеет каналом SSH, чтением stdout/stderr,
  ограничением ответа, монотонным тайм-аутом, отменой и кодом завершения.
  `SshClient` отвечает за соединение, pinning, редактирование секретов и отображение
  результата команды; успех требует exitCode=0.
- `ui/IconButtons` задаёт общую типографику и минимальную высоту, а фактическая высота
  определяется переносом текста. `ActionGridLayout` выравнивает высоту кнопок ряда.
  `DrawerLayoutPolicy` сохраняет половину экрана при обычном шрифте и расширяет меню
  при увеличенном, сохраняя область закрытия.

Граф зависимостей модулей сохранён. Две самостоятельные ответственности извлечены
из экранного/сетевого кода; это не полное разбиение MainActivity и FilesActivity.
Оставшиеся ограничения перечислены в AUDIT_2026-10-15.md.


## Файловый мод 0.11.6 — 20 октября 2026

- `core/TransferPaths`: имена и относительные пути провайдеров/SFTP проверяются до записи. Счётчики обхода ограничивают задание 10000 элементами и 48 уровнями.
- `transport/SftpClient.TreeSession`: одна сессия с прежним pinning на дерево, чтение без ссылок, создание папок, загрузка в уникальный временный файл и переименование после успешного окончания. Отмена и неизвестная длина потока не должны публиковать неполный файл.
- `app/TransferForegroundService`: владелец очереди, потоков и сессий; API экрана передаёт только ссылки на выбранные документы, маршруты и уже подтверждённый публичный fingerprint. Пароль/закрытый ключ в Intent не помещаются. Очередь сетевых передач переживает закрытие экрана, но не принудительное завершение процесса.
- `app/FilesActivity`: единые области телефона и сервера. `FileNodes` работает с разрешёнными SAF-документами, своей папкой сервера и доступными приложению MediaStore-загрузками. `DocumentFiles`/`ReceiveFolder` управляют выбором папки и созданием копий без перезаписи исходников.
- `transport/EmbeddedSftpServer`: событие успешного закрытия записи или окончательного переименования уведомляет владельца сервера. Чтение не запускает экспорт, временные файлы исключены. Авторизация первым ключом по-прежнему требует локального разрешения владельца.
- `app/AutoReceive`: отдельный исполнитель и SQLite-журнал завершённых загрузок. Копирование в Downloads/SAF начинается без Activity и подтверждения каждого файла. Ошибка назначения оставляет оригинал и ожидающее задание; повтор выполняется при старте сервера или явной команде. Журнал обеспечивает повтор, но не exactly-once: авария между публикацией копии и отметкой в SQLite может создать дополнительную копию.
- Сервер и сетевые передачи используют foreground-тип `connectedDevice` для связи с парным устройством; prerequisite `CHANGE_WIFI_STATE` уже объявлен. Уведомление остаётся видимым. Политики производителя, принудительная остановка и перезагрузка всё ещё могут завершить работу. Локальный совместимый экспорт 0.11.5 оставлен для старого внутреннего экрана, но не дублируется в новой навигации.
- `SshKeys.moveRoute` связывает новый адрес того же сервера с логической зашифрованной личностью. Старый fingerprint обязателен, отличный уже сохранённый fingerprint не заменяется. Новая сеть не отключает pinning.

Автоматические проверки и ограничения конкретной сборки приведены в RELEASE-0.11.6.md. Физическая установка отдельно от JVM/сборки instrumentation APK.


## Отмена и повтор 0.11.8 — 21 октября 2026

TransferForegroundService назначает заданиям request_id, который сохраняется при повторе. Приём задания и завершение синхронизированы: уже выполняющееся или недавно завершённое задание с тем же ID не ставится в очередь снова. Последние 256 успешных ID хранятся только в памяти процесса; намеренная новая операция получает новый ID. Это не серверный протокол идемпотентности и не журнал восстановления после убийства процесса.

Последняя неудачная передача хранится вместе с безопасной диагностикой. Успешное независимое задание её не стирает; успешный повтор того же ID снимает ошибку. Сохраняется именно последнее неудачное задание, а не неограниченная история неудачных передач. Ошибки телеметрии не меняют уже успешный результат копирования.

Проверка отмены выполняется до чтения, после чтения, после закрытия потоков и до публикации документа / переименования временного файла. При обработанной отмене удаляется только созданная текущим заданием копия. Уже завершённые файлы и исходники остаются. Отмена пуcтой очереди сразу показывает конечное состояние. Атомарная операция, начавшаяся после последней проверки, не откатывается задним числом. Ограничения повторов деревьев и process-local очереди описаны в инструкции.
