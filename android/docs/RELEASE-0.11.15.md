# LocalLS Android 0.11.15 — назначение файловых операций

Устанавливается поверх 0.11.14 без удаления приложения. Пакет и постоянный release-сертификат прежние; versionCode 35 > 34.

- Файловый экран и новое задание используют одно подключение и один проверенный fingerprint. Изменение общих настроек больше не отправляет старое выделение на другой сервер.
- После смены адреса, порта, пользователя, fingerprint или роли экран обновляется. Сохранённое состояние чужого сервера не восстанавливается; папка телефона сохраняется.
- Если подключение изменено, пока открыт системный выбор файлов/папки, приложение просит выбрать заново. Обычное пересоздание экрана с тем же подключением сохраняет назначение.
- Подтверждение создания папки, переименования и удаления на сервере проверяет актуальность подключения. Отложенное чтение выбранных файлов не отправляет их после перехода в другую папку.
- Уже поставленная передача сохраняет исходное назначение. Смена профиля не перенаправляет её; для остановки есть отмена очереди.

Проверки: 148 JVM-тестов и 7 Python-тестов, без ошибок и пропусков. На стенде проверены два SSH/SFTP-сервера с разными адресами, передача только исходному адресату, смена роли, fingerprint, восстановление экрана и выбор папки. Lint без ошибок, проверки подписи и совместимости обновления пройдены. Телефоны, установка на них и реальный Wi-Fi в среде разработки недоступны.

Инструкция настройки двух телефонов встроена в APK и опубликована с исходниками. Новые сетевые функции для произвольных Wi-Fi сетей остаются следующим этапом по плану.


Результат полного прогона: JVM {'tests': 148, 'failures': 0, 'errors': 0, 'skipped': 0}; Lint {'Error': 0, 'Warning': 26}; Python 7 тестов правил обновления/подписи. Аудиты проекта и архитектуры без ошибок, 87 production-классов / 5 модулей. Release и instrumentation APK собраны. ADB devices пуст; установка и реальные Android/OEM/Wi-Fi не проверены.

До исправления три из четырёх новых сценариев падали на production-0.11.14 (reproduce.log): выбранный файл старого сервера ставился в очередь с новым общим адресом; saved state старого сервера восстанавливал его путь после смены профиля; результат системного выбора файлов не отклонялся при смене подключения. Сохранение папки при неизменном подключении проходило. Предварительные ошибки компиляции тестовой обвязки устранены; воспроизведение относится к завершившемуся прогону из четырёх тестов, а не к ошибке компиляции.

FileConnection — неизменяемый снимок host/port/user/pin без закрытых ключей. FilesActivity использует его для списка и серверных операций; TransferForegroundService принимает этот же снимок вместо повторного чтения текущего профиля. Intent уже поставленного задания и его повтора сохраняет назначение. Закрытый ключ по-прежнему загружается из защищённого хранилища по маршруту при начале операции, строгая проверка pin выполняется до авторизации. Смена адреса/удаление ключа может сделать прежнее задание недоступным; автоматического перенаправления нет.

При onResume и перед отправкой/подтверждением серверного изменения проверяются адрес, порт, пользователь, pin и роль. При расхождении выбор/список сервера сбрасываются, поколение запроса инвалидируется, экран пересоздаётся. Режим только своего сервера имеет приоритет над прежним клиентским Intent. Локальная область и её история сохраняются независимо. Серверный saved state применяется только при совпадении контекста; для нового профиля берётся его собственная сохранённая папка RemotePlaces либо начальная папка. Закладки не стираются. Свой сервер не зависит от изменений параметров подключения к чужому серверу.

Контекст незавершённого системного выбора файлов/папки сохраняется в Bundle. При смене подключения результат отклоняется до выдачи URI-разрешений/чтения документов; при обычной ротации с тем же контекстом выбор работает. Асинхронное чтение метаданных прикреплённых файлов проверяет поколение и каталог, чтобы переход по папкам не менял назначение незаметно. Папка телефона выбирается отдельно и не зависит от адреса удалённого сервера.

Семь новых FileConnectionFlowTest используют реальное SSH/SFTP на разных loopback IP: обновление профиля, saved state для прежнего/нового сервера, смена роли и fingerprint, устаревший результат picker и фактическая передача при двух доступных серверах. В последнем тесте оба сервера принимают ключ: несмотря на смену глобального адреса, байты появляются только у адресата, выбранного снимком. FilePaneFlowTest дополнен положительным сценарием выбора папки после пересоздания экрана с тем же назначением. Управляемый Android-провайдер и Robolectric не заменяют проверку реальных телефонов.
