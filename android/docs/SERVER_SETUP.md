# LocalLS: графический мастер сервера

Мастер — дополнительная функция, а не замена штатного Termux.
Существующие sshd_config, host keys, работающий процесс sshd и boot-механизм
сохраняются. Изменение пароля требует явного переключателя и подтверждения.

## Граница автоматизации

LocalLS должен быть установлен на серверном и клиентском устройствах. Без SSH или приложения на
сервере первичная удалённая настройка невозможна. На серверном устройстве пользователь ставит
официальный Termux, открывает один раз для распаковки среды, предоставляет
системный доступ к его папке и разрешение RUN_COMMAND. Ручной ввод команд и
редактирование текстовых файлов не требуются; первый запуск Termux показывает
его штатный экран. Эти системные действия нельзя скрыть или подтвердить за пользователя.

Далее LocalLS выполняет подготовку в фоне. Сам мастер не содержит терминала,
редактора команд или окна с shell output. Ошибки показываются обычными сообщениями.
Первая установка OpenSSH требует интернета и доступного репозитория Termux.
Новый автозапуск не создаётся. На совершенно новом сервере после перезагрузки
можно снова нажать «Подготовить сервер»; действующая схема пользователя остаётся.
Папка файлов создаётся в приватном HOME/LocalLS; общую память телефона мастер
не делает доступной без системного разрешения пользователя.

## Безопасность

- SAF принимает только корневую папку com.termux.documents.
- Остальные свойства termux.properties сохраняются.
- Пароль преобразуется в бинарный штатный Termux auth hash на Android:
  PBKDF2-HMAC-SHA1, salt Termux!, 65536 итераций, 20 байт. Формат проверен по
  https://github.com/termux/termux-auth/blob/master/termux-auth.c и termux-auth.h.
  Он унаследован от Termux и не должен использоваться как общий формат хранения паролей.
- Пароль не попадает в RUN_COMMAND, argv, stdin, вывод команд, профиль или Bundle.
- Хеш хранится в приватном HOME/.termux_authinfo и получает chmod 600.
- Фоновый скрипт фиксирован. Пользовательские строки не интерполируются в shell.
- Не выполняются полный upgrade, kill/restart sshd, смена конфигурации или boot hooks.
- Существующие host keys не дополняются и не заменяются.
- RUN_COMMAND использует официальный explicit service и одноразовый explicit
  PendingIntent с приватным receiver, nonce и ограниченным временем действия.
- Сырые stdout/stderr не публикуются в интерфейсе, prefs или логах.
- Экспорт разрешён только после фактического SSH password login по loopback.
- Перед импортом публичного JSON пользователь сверяет ключ на серверном и клиентском устройствах.
  Конфликт с уже доверенным ключом блокируется; прежний сохранённый пароль
  очищается при импорте, чтобы не отправить его новому серверу.

Порт берётся из sshd -T. Если существующий daemon стартует с отдельным аргументом
-p, отличающимся от конфигурации, мастер обнаружит ошибку входа, не запуская второй
сервер. Такой случай требует согласовать порт штатного сервера.

## Быстрый запуск 0.9.1

«Настройки → Этот телефон — сервер» запускает безопасную подготовку без повторного
подтверждения, если штатный Termux и разрешения уже готовы. На новом устройстве
мастер показывает недостающие шаги. Пароль не заменяется автоматически; профиль
подключения к другому серверу сохраняется. Успешный callback отмечает роль устройства
как серверную только в настройках мастера. Для экспорта по-прежнему нужен реальный SSH-вход.

## Совместимость 0.9.2

В официальном Termux 0.118.3 успешный RUN_COMMAND возвращает `err = -1` и
`exitCode = 0`. Значение `err = 0` считается ошибкой. Сырой stdout/stderr
не сохраняется; для диагностики остаются только числовые коды и обычное сообщение.
Уровень фонового журнала передаётся строкой `"0"`, как требует Termux Intent API.

OpenSSH 10.5 выводит параметр `Port` с заглавной буквы. Мастер читает его без
учёта регистра и сохраняет совместимость с прежним `port`. Существующие
конфигурация, host key и процесс sshd при этом не меняются.

Интеграционный тест использует настоящий Termux и OpenSSH в Android-эмуляторе:
реальный password login, SFTP round-trip, повторный быстрый запуск мастера,
сравнение PID, sshd_config и fingerprint, проверка разрешения экспорта после входа.
Итог выполненного прогона приведён в BUILD_REPORT.md.
