# Аудит LocalLS Android — 15 октября 2026

## Область

Проверена текущая рабочая ветка `codex/android-server-wizard-readiness` на базе
`45482d1`, включая ранее сохранённые изменения мастера и файлового браузера.
Проверены направления зависимостей пяти модулей, SSH/SFTP, pinning, HTTPS,

## Найдено и исправлено

| Приоритет | Дефект | Исправление и проверка |
|---|---|---|
| P1 | `SshClient.runCommand` возвращал успех при ненулевом exit status | Выделен SshCommandExecutor, успех только при exitCode=0; настоящий SSH fixture проверяет 0 и 41 |
| P1 | Проверка браузера только по строке пути принимала старый ответ при A → B → A и после уничтожения экрана | DirectoryRequestState с поколениями; устаревшие ответы не меняют список, host и разрешение записи; два JVM-теста |
| P2 | stderr SSH не вычитывался, чтение непрерывного вывода обходило проверку срока внутри цикла | Оба потока читаются ограниченными блоками; общий лимит 64 КиБ, монотонное время, отмена; fixture проверяет stderr, превышение лимита и тайм-аут |
| P2 | Текст меню обрезался на ширине 160 dp даже при fontScale=1 | Воспроизведено на «Забыть сохранённый fingerprint»; естественная высота и перенос текста |
| P2 | При fontScale=2 обрезалась плитка «Проверить память» в меню | Высота по содержимому и одинаковая высота кнопок в каждом ряду; меню расширяется пропорционально системному шрифту, оставляя 24 dp для закрытия; расширен тест меню |
| P2 | GitHub CI не задавал LOCALLS_SECURITY_FIXTURE, поэтому сетевые JVM-тесты пропускались | Workflow поднимает изолированный AsyncSSH/HTTPS fixture, проверяет готовность и завершает его через trap; добавлен архив результатов app-тестов |

stdout и stderr вместе ограничены; stderr не выводится пользователю. Стандартные
диагностические команды `probe` продолжают читать stdout при ненулевом exit code:
отсутствие Termux:API не должно делать сам SSH недоступным. Действия `runCommand`
строго проверяют код завершения.

## Проверенные защитные механизмы

- SSH/SFTP проверяют известный host key до аутентификации; ключевой режим не
  переключается незаметно на пароль.
- HTTPS использует точный pin сертификата до отправки токена, проверку срока,
  запрет redirect и ограничение размера ответа. Legacy HTTP требует явной настройки.
- Пароль и токен хранятся AES-GCM, ключ — в Android Keystore; секреты не передаются
  в Intent и saved state. Backup отключён. Проверка физического Keystore отдельно
  на устройстве в этой среде невозможна.
- Установщик агента сохраняет существующие token/TLS/config и отказывает при
  небезопасных файлах, занятом порте и параллельном запуске.
- Release-сборка требует четырёх параметров подписи владельца. Создание нового
  ключа не решает обновление приложения, подписанного прежним сертификатом.

## Оставшиеся ограничения

1. **Подпись выпуска:** прежнего приватного ключа 0.9.4/0.9.5 в этой среде нет.
   Новый APK имеет прежнюю локальную debug-подпись, несовместимую с опубликованным APK.
   applicationId, versionName 0.9.5 и versionCode 14 не изменялись в рамках аудита.
2. **Очередь передач:** до сих пор принадлежит FilesActivity; foreground service
   только повышает приоритет процесса. Уничтожение Activity отменяет очередь.
   Для гарантированных фоновых передач нужен отдельный перенос владельца очереди
   в service и проверки Android 15+ timeout/перезапуска процесса.
3. **Крупные Activity:** MainActivity и FilesActivity остаются примерно по тысяче строк;
   новые компоненты устраняют конкретное смешение обязанностей, но полный перенос
   очереди и экранных контроллеров пока не выполнен.
4. **Общий Java package:** Gradle-модули имеют проверяемые зависимости, но используют
   package-private API в одном Java package. Дальнейшая изоляция требует публичных
   интерфейсов и отдельной миграции пакетов.
5. **Устройство:** adb не обнаружил подключённых телефонов/эмуляторов. Termux SAF,
   RUN_COMMAND, батарея, реальные IME и фоновые ограничения не испытаны на телефоне.
6. **GitHub CI:** конфигурация исправлена локально, запуск Actions на GitHub не выполнен.
   Существующие lint-предупреждения перечислены в журнале, не скрываются baseline.

## Проверка пользователем

- Открыть меню на маленьком экране при шрифте 100/150/200%, проверить длинные кнопки.
- Быстро менять каталоги и возвращаться назад; список и путь должны совпадать.
- Отправить/скачать файл и сравнить содержимое; проверить отказ при недоступном пути.
- На отдельном тестовом сервере выполнить неуспешную команду: UI не должен писать успех.
- Проверить сворачивание и возврат во время передачи; закрытие экрана пока отменяет её.
