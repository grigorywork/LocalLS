# LocalLS Android 0.11.14 — файловые области и роли

LocalLS Android 0.11.14 — папки телефона, файловые области и разделение ролей.

- «Место» в файловом менеджере задаёт папку области «Телефон». «Мой сервер → Папка сохранения» задаёт автоматический приём сервера. Эти настройки больше не меняют друг друга. Прежний выбор при первом открытии сохраняется, существующие файлы не перемещаются.
- Две области «Телефон» / «Сервер» доступны на обоих устройствах. Для области телефона добавлено меню «⋮»: выбор всех элементов, снятие выбора и создание папки в доступном Android-каталоге. Направления копирования остаются общими кнопками «На сервер» и «На телефон».
- Исправлены история «Вверх» после пересоздания экрана, восстановление корня загрузок и переименование собственных файлов LocalLS в загрузках. Занятые имена не перезаписываются. При обновлении списка устаревшие элементы и выделение временно недоступны.
- В режиме своего сервера клиентская сеть и настройки мониторинга чужого сервера скрываются. Клиентский мониторинг приостанавливается, его предпочтение сохраняется и возвращается общим ползунком «Подключаться к другому серверу». Свой сервер, автосохранение и фоновые передачи продолжают работать.

Сохранение: открой «Файлы», нажми «Место», выбери доступную папку Android, разреши доступ один раз. Выбери файл/папку в области сервера и нажми «На телефон». Для автосохранения на телефоне-сервере выбери папку отдельно в «Мой сервер». Подтверждать каждый принимаемый файл не нужно. Android может ограничивать защищённые каталоги и корень общих загрузок; кнопка «Загрузки» показывает Download/LocalLS, остальные доступные папки выбираются через Android.

[Инструкция](https://github.com/grigorywork/LocalLS/blob/android-v0.11.14/android/app/src/main/assets/phone-setup.txt) встроена в APK. [План следующих этапов](https://github.com/grigorywork/LocalLS/blob/android-v0.11.14/android/docs/FILE_MANAGER_PLAN.md) сохраняет порядок владельца: сначала проверить файлы на обоих телефонах, затем по команде «давай последний мод» расширять интерфейс и сценарий других Wi-Fi. В этом выпуске сетевые маршруты и SSH-ключи не менялись.

Установи APK поверх 0.11.13 без удаления и очистки данных. Постоянная release-подпись прежняя, versionCode 34 > 33. После обновления включи сервер вручную.

140 JVM-тестов и 7 Python-тестов прошли без ошибок и пропусков, lint без ошибок. Реальные телефоны не подключены: установка, Android-провайдеры конкретного устройства, Wi-Fi и OEM-фон не проверялись. Прежние ограничения очереди и повторного копирования папок сохраняются.


Проверки: JVM {'tests': 140, 'failures': 0, 'errors': 0, 'skipped': 0}, Lint {'Error': 0, 'Warning': 26}; Python 7 тестов правил обновления/подписи. Аудиты проекта и архитектуры без ошибок, 86 production-классов / 5 модулей. Release и instrumentation APK собраны. ADB devices пуст; установка и реальные Android/OEM/Wi-Fi не проверены.

Воспроизведение: шесть новых тестов упали на production-0.11.13 (reproduce.log): общий ключ папки для телефонной области и серверного автосохранения; потеря истории «Вверх» после saved state; доступность старого выделения во время обновления; клиентская сеть в режиме сервера; скрытые настройки мониторинга могли менять сохранённое предпочтение; клиентский мониторинг продолжал планироваться в серверной роли. После исправления целевой прогон прошёл. Новые сценарии расширены проверкой остановки старого клиентского задания, совместного ручного/автоматического сохранения, корня загрузок, создания папки и переименования собственных загрузок.

Папки назначения: введён отдельный FileNodes.PHONE_TREE. При первом чтении копируется прежний выбор ReceiveFolder.TREE, сохраняя совместимость и существующие URI-разрешения. После этого изменения независимы. Файловый экран и назначение фоновой ручной копии по умолчанию используют PHONE_TREE; AutoReceive продолжает использовать ReceiveFolder.TREE. Явное назначение уже поставленного задания сохраняется в Intent. Выбор места не переносит ранее принятые файлы. Сервер по-прежнему предоставляет приватную папку LocalLS, а не всю память телефона.

Файловые операции: у телефона добавлено меню контекста области, использующее общие функции выбора и создания папки; серверное меню остаётся единственным местом общих операций очереди. Для Downloads/MediaStore создание пустой папки не предлагается, поскольку MediaStore сохраняет файлы, а не пустые каталоги. Собственные MediaStore-файлы переименовываются через update DISPLAY_NAME, SAF-документы — через DocumentsContract. При коллизии имён в области телефона операция отклоняется, включая другой регистр. Исходники и чужие записи не перезаписываются. Системные разрешения провайдера остаются обязательными.

Навигация: сохраняются стеки phoneBack/serverBack, при смене ширины экран пересоздаётся для расположения областей рядом/вертикально. Downloads-root имеет специальное читаемое имя при восстановлении Bundle: прежняя общая проверка имени отвергала символ / в его метке. Асинхронный список телефона защищён поколением запроса; старый результат не заменяет новый. При загрузке списки временно отключены, выбор очищается, действия копирования зависят от готовности областей. Выбор верхнего уровня ограничен 64 элементами с понятным сообщением; вложенные файлы папки считаются отдельно сервисным лимитом. Проверки коллизий перед rename не являются межпроцессной файловой транзакцией: окончательная запись зависит от провайдера Android.

Роли: общий DeviceRole используется главным экраном, настройками, файловым менеджером и клиентским мониторингом. В serverOnly режиме скрыты чужое подключение/клиентская сеть/клиентский мониторинг. Скрытое сохранение настроек не меняет предпочтение. JobScheduler отменяет клиентский мониторинг; устаревшее задание не выполняет сетевую проверку в этой роли. При включении общего клиентского ползунка сохранённое предпочтение мониторинга снова учитывается. Серверная foreground-служба, AutoReceive и очередь файловых передач этим не выключаются. Роль управляет интерфейсом и поведением фонового клиента, а не добавляет отдельную систему пользовательских прав.

Проверки провайдеров: SAF DocumentsProvider моделирует реальные файлы в отдельных каталогах Phone и Auto. Совместный тест проверяет байты ручной копии в Phone, автоматической копии в Auto и неизменённого серверного исходника. Экранный тест проверяет создание папки только в выбранном каталоге; MediaStore-провайдер проверяет update имени и отказ занять другое имя. Провайдер документов зарегистрирован в PackageManager с DOCUMENTS_PROVIDER, что требуется для корректного определения DocumentsContract URI. Это управляемые провайдеры Robolectric, не аппаратная проверка поставщиков Android.

Тестовая среда: первый общий прогон выявил JNI UnsatisfiedLinkError в native SQLite Robolectric при смешении sandbox-конфигураций. Изолированный прогон прежних 10 SQLite/AutoReceive-тестов прошёл. JVM-тесты app теперь получают отдельный процесс на класс (forkEvery=1), сохраняя native SQLite и все проверки; Совместный сценарий UI и сохранения включён в отдельный класс native SQLite/AutoReceive-проверок; финальный журнал — verified-build3.log. Android runtime-код SQLite и сам APK этим параметром не меняются. Финальный полный прогон включает 140 JVM-тестов без ошибок/пропусков; отключения SQLite-проверок нет.

План FILE_MANAGER_PLAN.md отражает текущую просьбу: довести файлы и разделение ролей, затем реальная проверка владельцем и отдельный следующий этап по команде. Новые сетевые возможности в этой ревизии не внедрены. Существующие механизмы смены IP с сохранением пары и pin остаются; общий маршрут между сетями по-прежнему необходим. Не добавлены широкие права доступа к чужим файлам или обход ограничений Android.
