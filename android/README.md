# LocalLS v0.9.3

Android-пульт и SFTP-проводник для личного сервера на Termux/OpenSSH.
Продолжение Home Server Control; рабочая v0.8 сохранена отдельно.
Название и значок обновлены: облако с золотой молнией.

## Проверка доступа и диагностика 0.9.3

Мастер проверяет разрешение внешних команд стандартным Properties parser до записи
и повторным чтением файла после записи, прежде чем вызывать RUN_COMMAND. Исправлен
случай продолжения последней строки: разрешение больше не становится частью
предыдущего значения. Некорректный файл не меняется и новый пароль не записывается.

Отказ RUN_COMMAND показывает фиксированные инструкции по известным признакам
Termux и числовые коды. Сырой errmsg, stdout/stderr и секреты не сохраняются.
Кнопка «Помощь с доступом Termux» открывает Termux или системные разрешения LocalLS.
В Termux 0.119 настройки разрешений кэшируются. При первой подготовке мастер
открывает Termux, отправляет штатный пакетный reload_style без пересоздания Activity
и продолжает RUN_COMMAND после возвращения кнопкой «Назад». В Termux нужно подождать
несколько секунд, вводить команды не требуется. Процесс и схема запуска sshd не меняются.
Версия Termux отмечается применённой только после фактического успешного callback.
Реальный policy refusal очищает эту отметку, чтобы повторная подготовка применила настройки.

## Исправления 0.9.2

Мастер совместим с фактическим протоколом Termux 0.118.3: успешный код `err = -1`
больше не считается ошибкой, а `err = 0` корректно отклоняется. Порт определяется
без учёта регистра `Port`/`port`, что поддерживает новые OpenSSH 10.5 и прежние версии.
Параметр уровня журнала передаётся строкой согласно официальному RUN_COMMAND API.
Ошибки разрешений, обновления пакетов и установки OpenSSH показываются раздельно,
без публикации сырых stdout/stderr. Результаты реальной проверки — в BUILD_REPORT.md.

## Wi-Fi на серверном телефоне

Запусти LocalLS на самом серверном телефоне: «Меню → Wi-Fi этого телефона».
Введи SSID и пароль WPA2 (8–63 печатных ASCII символа) либо отметь открытую сеть.
Пароль не сохраняется в настройках, состоянии Activity, диагностике или логах.

На Android 11+ сеть передаётся исключительно доверенному системному обработчику
добавления Wi-Fi; Android показывает подтверждение сохранения. На Android 10 LocalLS
передаёт сетевую рекомендацию: нужны разрешение местоположения и разрешение рекомендации
в уведомлении Android. Выбор подключения выполняет система; если сеть не переключилась,
используй кнопку «Системные настройки». На Android 7–9 подключение выполняется через системные настройки.

Статус показывает фактически доступную Wi-Fi сеть и её IPv4, а не успех отправки команды.
LocalLS не создаёт второй мост и не меняет Wi-Fi удалённого телефона. SSH использует текущую сеть Android.
После смены Wi-Fi IP сервера может измениться — обнови профиль на клиенте. Системное подтверждение,
реальное переподключение и ограничения батареи надо проверить на физическом серверном устройстве.

## VPN телефона, компьютера и сервера

Тумблер VPN находится только в боковой шторке. Используется отдельный официальный
Tailscale Android-клиент и его публичные CONNECT_VPN / DISCONNECT_VPN broadcasts.
LocalLS не создаёт фиктивный туннель и не включает VPN на чужих устройствах.

1. Установи Tailscale на серверное устройство, телефон и ПК, войди на них в одну tailnet.
2. На Android заверши первоначальный вход и разрешение VPN в Tailscale.
3. В LocalLS укажи Tailscale IP сервера (100.x.x.x) или MagicDNS-имя в VPN-профиле.
   Порт 8022 и пользователь u0_a606 остаются прежними.
4. Используй тумблер для управления VPN телефона. В другой сети выбирай VPN-профиль.
   На ПК подключай SFTP-клиент к тому же Tailscale IP/имени и порту 8022.

Дома адрес 192.168.1.82 сохраняется; включение VPN не переписывает профили и не включает
auto fallback. Обычный Tailscale без exit node сохраняет маршруты домашней сети.
При exit node включи Allow LAN access в Tailscale на каждом устройстве.
Тумблер отражает обнаруженный VPN Android; отправленная команда не считается
успешным подключением. Без клиента показываются инструкции по установке.
Если клиент не поддерживает broadcast API, открой его и переключи VPN вручную.
Готовность SSH и доверие к fingerprint проверяются отдельно.

## Графический мастер сервера

«Инструменты → Сервер → Мастер настройки» открывает мастер.
Установи LocalLS также на серверное устройство. Подготовка выполняется на нём; импорт — на устройстве, с которого будешь подключаться.

1. Установи официальный Termux с F-Droid и открой один раз для установки среды.
   Ручной ввод команд или редактирование файлов не нужны. Первый запуск Termux
   открывает его штатный экран; после установки среды вернись в мастер LocalLS.
2. Через системный выбор папок разреши доступ к корню раздела Termux.
3. Для нового сервера отметь «Задать новый пароль сервера», введи пароль дважды,
   разреши RUN_COMMAND и нажми «Подготовить сервер». На уже настроенном серверном устройстве
   оставь переключатель выключенным, чтобы сохранить пароль.
4. Мастер включает официальный allow-external-apps, сохраняя остальные свойства.
   Пароль преобразуется в штатный бинарный PBKDF2-HMAC-SHA1 хеш Termux
   (65536 итераций, 20 байт); открытый пароль не передаётся в команды или файл.
   Хеш остаётся в приватной папке Termux как при обычном passwd.
5. При отсутствии OpenSSH выполняются apt update/install без полного upgrade.
   Конфигурация сохраняется (--force-confold), существующие host keys сохраняются.
   Если sshd уже работает, второй экземпляр не запускается. Мастер не добавляет
   автозапуск и не останавливает/перезапускает существующий sshd.
6. «Проверить SSH и пароль» выполняет настоящий вход к локальному sshd.
   Только успешный вход разрешает экспорт профиля. Проверь Wi-Fi IP сервера
   в поле формы, сохрани LocalLS-server.json и передай его на другое устройство.
7. На устройстве для подключения выбери «Импорт профиля», сверь отпечаток с экраном сервера,
   затем введи пароль на основном экране приложения. В профиле пароля и токенов нет.
   Замена уже доверенного ключа при импорте блокируется.

Серверная папка — Termux / LocalLS. Политика разрешений и ограничения батареи
на серверном устройстве требуют проверки на устройстве. Первоначальная установка,
системное разрешение папки и первый запуск Termux остаются действиями пользователя.
После перезагрузки мастер использует существующую схему автозапуска, если она есть;
на новом сервере его можно запустить снова кнопкой «Подготовить сервер».
VPN на каждом устройстве требует отдельного входа в Tailscale.

## Что сохранено

SSH/SFTP pinning до передачи пароля, Android Keystore, Local/Tailscale-профили,
отключённый по умолчанию fallback, очередь передач, один retry, прогресс/ETA/скорость,
foreground service, CPU/Wi-Fi locks, история, mkdir/rename/удаление файла или пустой
папки, диагностика, discovery, мониторинг, iperf3 и независимый серверный агент.
Файлы realme-agent и схема запуска sshd не изменены.

Очередь выполняется в FilesActivity. Сворачивание через Home поддерживается;
закрытие/уничтожение экрана отменяет очередь. При обрыве overwrite upload возможен
частичный целевой файл; атомарная отправка запланирована в основе v1.0.
Смена темы не пересоздаёт FilesActivity во время активной передачи.

## Сборка

JDK 17, Gradle 9.6.0, AGP 9.4.1, Android Platform android-37.0, Build Tools 36.0.0.
minSdk 24, compileSdk/targetSdk 37. applicationId com.bitpoint.homeservercontrol
сохранён для обновления поверх предыдущего APK; versionCode 12, versionName 0.9.3.

```bash
python3 tools/audit_project.py
./gradlew clean assembleDebug :app:assembleDebugAndroidTest :app:lintDebug
mkdir -p artifacts
cp app/build/outputs/apk/debug/app-debug.apk artifacts/LocalLS-v0.9.3-debug.apk
python3 tools/verify_apk.py --sdk "$ANDROID_SDK_ROOT"
adb install -r artifacts/LocalLS-v0.9.3-debug.apk
```

На Windows: `gradlew.bat clean assembleDebug`; bootstrap scripts находятся в tools.
Актуальный размер, SHA-256, реальные результаты сборки/тестов и ограничения —
в BUILD_REPORT.md. Физические устройства клиента и сервера и вход в Tailscale нужны для
проверки настоящей сети, крупных файлов и ограничений батареи.

## Иконки, серверное меню, скачивание и сворачивание

На Dashboard и в панелях проводника — иконка сверху и маленькая подпись снизу.
В раскрывающихся разделах — компактные строки с иконкой слева и стрелкой справа. Контур кнопок —
тонкий полупрозрачный чёрный на всех темах. В шторке «Сервер» открывает отдельное popup:
мастер, Включить SSH, Отключить SSH, Перезапустить SSH, статус и доступ к серверному агенту.
Эти команды управляют SSH-службой; питание серверного устройства не меняется. Агент нужен отдельно,
чтобы снова включить SSH после его остановки. Существующая схема сервера не изменена.

В проводнике нажми «Выделить», выбирай файлы в разных серверных папках. Папки по-прежнему
открываются обычным нажатием. Долгое нажатие на файл также позволяет выделить его.
«Скачать выбранное» открывает системный выбор папки на телефоне; после подтверждения
файлы скачиваются через очередь с прогрессом, графиком и историей. Существующие локальные
файлы не заменяются: одинаковые имена получают номер. Выбор до 256 файлов сохраняется
при переходах между папками и recreate. Целые папки рекурсивно не скачиваются.

«Свернуть» доступно сверху в проводнике. В главной шторке эта кнопка убрана; обычная кнопка Home продолжает сворачивать приложение. Задача уходит в фон,
в Android-шторке остаётся уведомление LocalLS для возврата к тому же экрану. «Убрать»
убирает только это уведомление; активная передача имеет своё foreground-уведомление.
При возвращении в приложение уведомление сворачивания снимается. На Android 13+
нужно системное разрешение уведомлений. Постоянное уведомление само по себе не является
бесконечным foreground service: при отсутствии передачи Android вправе выгрузить процесс.

`tools/offline_android_build.py`: реальные AAPT2, javac, D8, zipalign и apksigner.

Для Kotlin 2.3.21 применяется D8 9.4.24 из официального cached AGP builder 9.4.1.
Создаётся `artifacts/LocalLS-v0.9.3-preview.apk`, читаемый Android build-tools.
Это настоящий Android APK, однако SDK-сборка не подменяет обязательный Gradle gate.
7 октября 2026 дополнительный сетевой доступ позволил повторить полную Gradle-сборку:
`BUILD SUCCESSFUL`. Актуальные функции теперь входят в `artifacts/LocalLS-v0.9.3-debug.apk`;
preview не заменяет итоговый APK. SHA, версии, реальные результаты
проверок и ограничения устройств указаны в BUILD_REPORT.md.
